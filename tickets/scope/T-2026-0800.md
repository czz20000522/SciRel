# 电荷交换速率系数的 `energy_ev` 在高能支充当束速度，API 语义待裁决

## 要决定的问题

本函数在高能支把 `energy_ev` 当成束速度，但合同与 docstring 从未写明。要决定的是：这个 API 的 `energy_ev` 语义是否应当显式化（改名、拆函数、还是统一两支语义）。

## 现象

`evaluate_atomic_hydrogen_charge_exchange_rate(temperature_ev, energy_ev)` 在任一参数超过 `2.01e4` eV 时进入积分支。该支把 `energy_ev` 当成**由热速度归一化的束速度**：

```python
beam_speed = 0.0 if energy_ev == 0.0 else math.sqrt(energy_ev / temperature_ev)
```

于是分布被平移，返回值是**束-靶速率系数**。实测（T = 3.0e4 eV 固定）：

| energy_ev | rate (m^3/s) |
|---|---|
| 2.1e4 | 4.576276e-14 |
| 5.0e4 | 2.831869e-14 |
| 1.0e5 | 1.214621e-14 |
| 2.0e5 | 2.214073e-15 |

**同一温度下相差 20.7 倍。** 由独立消费者 C4 发现：按其合同文字（"对着等质量麦克斯韦相对速度分布积分"）复现不出这些数，比值差 5.3×–83.8× 且随 (T,E) 单调变化。

## 已执行的处置

合同与 docstring 原本只写"对着等质量麦克斯韦相对速度分布积分"与"求积省略 250 keV 以上"，**没有一处提到分布被平移**。按真值链第 1 类（合同与代码不符 → 合同错了），已改写合同 `scope` 与 docstring `Notes`，明确写出 `sqrt(energy_ev/temperature_ev)` 的束平移与由此产生的强 `energy_ev` 依赖。**实现未改。**

## 待裁决的问题

签名把 `energy_ev` 与 `temperature_ev` 并列，读起来像"束能量 vs 等离子体温度"，也像"两温度下的速率系数"。但实现把前者变成分布位移，后者变成分布宽度，两者不是同一类量。需要裁决：

- 这个 API 是否应当显式命名为束能量（例如 `beam_energy_ev`），或拆成两个函数（纯热速率 / 束-靶速率）？
- 低能支的 9×9 双变量对数拟合以 (log E, log T) 为自变量，高能支以 `sqrt(E/T)` 为位移——**两支对 `energy_ev` 的语义不同**（前者是碰撞能量，后者是束速度），这是否是本意？
- 若两支语义应当一致，则需要改实现（属物理改动，须走分级评审），本单不预设方向。

## 选项

- **A（零改动，现状）**：保留签名与两支语义差异，仅在合同里写明（**当前已执行**）。代价：同一参数名在两支含义不同，外部消费者容易误用；C4 已经因此无法完成"速率系数"任务。
- **B（改命名，不改物理）**：把参数改成 `beam_energy_ev` 并在 docstring 写明两支的用法差异。代价：对外签名变更，需 API 评审与迁移说明。
- **C（拆函数）**：`..._thermal_rate(T)` 只依赖 T，`..._beam_target_rate(T, E_beam)` 显式两参数。代价：新增公开表面，与"能力边界冻结"冲突，需维护者批准。
- **D（统一语义）**：让低能支也用束平移，或让高能支改成纯热平均。代价：属于物理改动，必须附独立依据与前后对比，走分级评审。

## 各方意见

- **独立消费者（C4）**：按合同文字无法复现该函数的数值，因此未把速率系数作为任务答案交付；要求合同先写清 E 的作用。
- **集成者**：已确认机制是束平移，非数值伪影；已按第 1 类改合同、不动实现；主张至少采纳 A，倾向 B。

## 不决定的后果

外部消费者会把返回值当成纯热速率系数使用。在 T=3e4 eV 时按错语义取值可偏差一个量级以上，且不会触发任何警告——合同不写清、签名不区分，这个错用无法被调用方察觉。

## 裁决（2026-11-18，维护者；平台上仍待记录）

维护者在会话中直接裁决 W。`decisions` 与 `resolution` 按 `tickets/README.md` 由审核平台写，本 agent 不代填，所以 frontmatter 仍是 `open`——**但下面列的执行已经落地**，审核平台记录后可改为 `applied`。

**选了 W：撤下。** 维护者口径是「像这种不确定的，默认撤下」。

理由不是"这个函数算错了"——束平移本身可能符合设计。理由是**调用方无法知道 `energy_ev` 在两支里是两种量**：名字相同、形状相同、失败行为相同，只有在 `>2.01e4 eV` 时才悄悄变成束速度。这类接口输出的数看起来永远是对的。
