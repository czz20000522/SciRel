## 要决定的问题

`scirel/kinetic/generalized_dispersion.py` 的实轴主值分支里有一段近奇异替换：

```python
def regularized(velocity):
    offset = velocity - real_point
    if abs(offset) < 1e-7:
        return float(derivative(real_point))
    return (density(velocity) - density_at_point * np.exp(-offset * offset)) / offset
```

要决定的是：`|offset| < 1e-7` 这个分支是否应在任何公开输入下生效。

仓库内可直接复现的事实：

1. 插桩副本在 `_transform` 入口与目标分支体内各写标记文件。同一副本里**阳性对照（入口）每次调用命中 2 次**
   （`Z` 与 `Zp` 各一次），证明插桩生效。
2. 三种实轴输入下**目标标记均为 0 次**：

   | 输入 | `x` 与 mesh 的关系 | 入口标记 | 目标标记 |
   | --- | --- | --- | --- |
   | `x=0.6`, `mesh=[-20,-2,0.6,2,20]` | 等于 mesh 断点 | 2 | 0 |
   | `x=-0.7`, 同一 mesh | 面板中点（对照） | 2 | 0 |
   | `x=0.0`, `mesh=[i*0.25 for i in -40..40]` | 等于密集 mesh 断点 | 2 | 0 |

3. 原因：求积后端（SciPy `quad`）不对面板端点求值。`edges` 里 `real_point` 确实作为面板边界出现，但
   高斯-克朗罗德节点全在面板内部，最近节点与 `x` 的距离是面板长度的一个固定分数，远大于 `1e-7`。
4. 因此该分支对不更换求积后端的公开调用不可达：收紧 `epsabs`、加密 mesh、把 `x` 放在断点上都不触发。
5. 后果之一：变异测试把 `derivative(real_point)` 改成 `0.0` 后存活，而这是"从未执行"，不是"测试抓不住"。

## 选项

- **A 删除该替换分支**：代码少一条不可达路径，读者不再误以为存在"节点命中奇点"的防护。代价：若将来更换
  会评估端点的求积后端、或允许调用方自定义节点，需要重新引入这层防护。
- **B 保留并声明**：行为不变、零改动风险；合同明确写"防御分支、公开输入下不可达、无测试可覆盖"。代价：仓库
  内长期留一条永不执行的分支，每次审查都要重新确认它仍不可达。

## 各方意见

- 证据侧（本单）：倾向 B。该分支是数值防护的常见写法，其存在本身有可读价值；但必须由合同声明不可达，
  否则读者会把它当成已验证的鲁棒性。
- 合同侧：B 需要一条 `known_limitations`，A 需要删除合同里相关措辞；两者都要中英同步。
- 待补：需要第二份独立评审意见（本单要求 2 人）。

## 不决定的后果

- 若两个选项都不裁决：该分支保持"存在且无测试"的状态，`generalized-hilbert` 的变异验证缺口无法闭合，
  任何"节点命中奇点时有防护"的论证都没有证据支撑。
- 合同里已经按安全默认写了 `known_limitations` 并引用本单，因此**不会**出现"错误行为被写成已声明"的情况；
  未裁决的成本是这条缺口长期挂在 C1 账上，而不是产生错误结果。
