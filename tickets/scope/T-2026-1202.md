## 要决定的问题

`scirel.kinetic.rational-solve-matrix` 的合同声明了 **46 个输出字段**，公开入口
`scirel.kinetic.dispersion.rational:solve_matrix` 实际返回 **9 个**：

```
返回键: d, omega, V, w, wi, ind, indices, backward_residual, wg
声明了但未返回（37 个）: all_finite, infinite_count, canceled_poles, rational_residual,
  pencil_residual, constant, poles, residues, accepted, alpha, beta, A, ...
```

要决定的是：这个资产的**公开输出集**是哪一个——A：裁剪合同到实际返回的 9 个（内部诊断归私有，
不作为公开契约）；B：把这 37 个内部诊断也变成公开输出（入口返回完整记录）。

## 仓库内的事实（可直接复现）

1. 合同与实现都能读到：

   ```sh
   python3 -c "import json;d=json.load(open('catalog/examples/scirel.kinetic.rational-solve-matrix.json'));print(len(d['outputs']))"
   # 46
   ```

   ```sh
   PYTHONPATH=src python3 -c "
   from scirel.kinetic.dispersion.rational import equilibrium, pole_table, point_matrix, solve_matrix
   eq = equilibrium('es1d', [[1,1,1,1,0]])['state']; tab = pole_table('es1d', 4)['state']
   m = point_matrix('es1d', {**eq, **tab}, k=0.4)['state']['M']
   print(sorted(solve_matrix(m, model='es1d')))"
   # ['backward_residual','d','ind','indices','omega','V','w','wg','wi']
   ```

2. **那 37 个字段确实存在，但在私有模块里**：`_harris_descriptor.py:53-54` 产出 `poles`/`residues`，
   `_rational_frequency.py:29,36,37,78` 产出 `all_finite`/`poles`/`residues`。两者都以 `_` 开头，
   不在公开命名空间。
3. 合同 `example.code` 只断言 `len(r['omega']) == 4` 与 `max(r['backward_residual']) <= 1e-11`，
   即示例本身只用了返回的 9 个键里的 2 个——**示例与合同的 outputs 表也不一致**。
4. 这不是孤例：另有 7 份合同声明了 25 个以上输出
   （`closures.reduced-hall-drift` 48、`kinetic.spectral-plasma-state` 39、`mirror.grid-mirror-kinetic-closure` 37、
   `kinetic.spectral-dispersion-scan` 28、`equilibrium.free-boundary-anisotropic-picard` 27、
   `equilibrium.reduced-hall-anisotropic-picard` 26、`equilibrium.kinetic-mirror-hall-equilibrium` 25）。
   它们的实际返回集尚未逐个核对，本单以 `rational-solve-matrix` 为样本。

## 各方意见（为什么现在定不下来）

- **外部消费者（C4 第二轮）**：报的是"46 个声明输出只返回 9 个"。它明确写了不敢替维护者选：
  "两种可能——合同把概念名当成了字段名，或入口该返回映射却没返回——需要维护者裁决"。
- **支持 A 的一方**：合同的 37 个字段里，`poles`/`residues`/`alpha`/`beta`/`A`/`pencil_residual` 都是
  数值诊断量，不是物理结果；把它们变成公开契约意味着要逐个写单位与适用范围，而它们目前只出现在
  私有模块的中间记录里，没有任何外部使用者。
- **支持 B 的一方**：`backward_residual` 已经在返回集里，说明"残差类诊断可以是公开的"；若极点与
  残差对排查重要，先裁剪再将来重开资产，会让已经依赖这 46 个名字的读者（例如照合同写的消费者）
  第二次改代码。
- **尚缺的证据**：没有记录过任何人实际读过这 37 个字段中的哪一个。若审核人知道外部有使用者，
  这条证据会直接决定选项。

## 选项

- **A（裁剪合同）**：公开契约与公开行为一致，外部消费者能靠合同取到每一个声明的值。代价是那 37 个
  内部诊断**在公开面上失去名字**，将来若要公开需另立资产。符合"合同是代码的衍生品"与当前
  "能力边界冻结"的立场。
- **B（公开完整记录）**：调用者能拿到极点、残差、验收标志等诊断，对排查很有用。代价是把 37 个
  内部字段一次性变成**公开契约**，需要为每个字段写单位、适用范围与失败行为，并承担向后兼容；
  在冻结期这与"先还债、不加新能力"直接冲突。

## 与已采纳 API 规范的关系

`skills/development/scirel-code-style/references/api-spec.md` 要求"返回多个量的函数返回 `Result`"。
本单不改变该要求；它决定的是**哪些量算"返回的量"**。

## 不决定的后果（已执行的安全默认）

实现不动；合同暂不裁剪；任何消费者遇到这 37 个字段只能记 `cannot establish`。
`tests/tooling` 目前**没有**"声明输出集必须等于实际返回键集"的检查器，所以这类不一致不会被门禁拦住——
是否要加这条检查器，随本单一起决定。
