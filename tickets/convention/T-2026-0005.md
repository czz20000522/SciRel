## 要决定的问题

`scirel.geometry` 的同一个点族里存在**两套角度单位**：`Mesh.theta` 属性返回**弧度**（`arctan2(R, Z)`），
而 `ThetaChord` / `SphericalRChord` 的构造器接受**度**（`theta0`、`tpts` 的单位字段写的是 `degree`）。
两者混用相差 180/π，而代码不会告警。要决定的是：长期保持双单位并靠文档指路（B，当前安全默认）、
统一成一种单位（A）、还是让构造器接受单位标记（C）。

### 仓库内的事实（可直接复现）

```python
>>> import numpy as np
>>> from scirel.geometry import PointsMesh, ThetaChord
>>> PointsMesh([0.2], [0.3]).theta          # 弧度
array([0.5880026])
>>> ThetaChord([0.5880026], 1.0).R          # 把弧度当度喂进去
array([0.01027174])
>>> ThetaChord([90.0], 1.0).R               # 真正的四分之一圈
array([1.])
```

- 两份合同各自都声明了自己的单位，代码与各自合同一致——**这不是合同错，也不是代码错**，错在跨资产误用
  在文本层面挡不住。
- 证据：`tests/geometry/test_frame_convention_evidence.py::test_mesh_theta_property_returns_radians_while_the_constructors_take_degrees`
  同时钉住了两件事，并断言混用后 R 相差超过 1e-2。

## 选项

**A. 统一为一种单位（例如全部改为度，或全部改为弧度）。**
依据：消除误用面。影响：`Mesh.theta` 或两个构造器之一的行为变更，属对外承诺变更；调用方（含示例与外部
消费方）会静默得到不同数值，必须配 deprecation 窗口与迁移说明。冻结期内不做。

**B. 保持双单位，用文档互相指路（当前安全默认）。**
依据：零风险，行为不变。影响：误用仍需读者看文档；已通过三份合同的 `known_limitations` 与测试钉住。

**C. 构造器接受显式单位参数（如 `angle_unit="deg"|"rad"`）。**
依据：既保留兼容又让单位显式。影响：签名变更（新增关键字），需要 API 评审与向后兼容策略；`Mesh.theta`
仍需决定是否也接受单位开关。

## 各方意见

支持 A 的是长期一致性；反对 A 的是这会打断现有调用方，且两个单位的语义在各自语境里都自然（属性是数学
角度、构造器是工程角度）。支持 B 的是零风险；反对 B 的是文档挡不住仓促调用。支持 C 的折中最好，但签名
变更在冻结期内同样需要人工批准。

## 不决定的后果（已执行的安全默认）

`points-mesh`、`theta-chord`、`spherical-r-chord` 三份合同的 `known_limitations` 已写明"`Mesh.theta` 返回
弧度、构造器接受度、两者不可互换"并引用本单 `T-2026-0005`；测试同时断言两种单位与混用后的偏差。
