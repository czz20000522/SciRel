# 科学需求提取

这是项目内、Git ignored 的个人私有方法。将来源项目实际具备的科学能力转成来源中立、可独立理解、可判定的需求题；来源身份、源码映射和参考运行留在私有材料中。项目路径、运行主机与存储约定由当前任务提供，不写入此方法。

## 先判断范围与投入

先读绑定的源码版本、说明、论文和案例，交叉盘点物理任务、模型、输入输出关系及必要适用条件。排除 IO、绘图和纯包装代码并说明理由，不按函数数量计能力，也不按当前消费库已经具备的功能裁题。未完成实现、语义不明和环境受阻项仍在清单中可见。

给出需求数量的合理区间、划分依据、工作量与主要不确定性，区分题面整理、参考复现、判据准备和人工科学审查。用户要预览时，先选一两道覆盖差异明显、来源路径清楚的题，实测一题的成本后再修正全项目估算。详见 [覆盖与估时](references/coverage-and-estimation.md)。

## 形成题目

题目可以是单能力、组合或完整应用。公开部分必须讲清物理目标、适用模型、输入、输出、必要科学约定及完成/失败规则，不固定来源函数名、内部数组偶然顺序或特定实现方法。

能改变答案的单位、符号、归一化、轴序、边界/初值、分支选择、常数等不能只藏在源码或隐藏参考里。仅列相关字段；缺定义时保留 `HOLD`，不靠一次成功运行补齐科学语义。多解、相位自由度、集合顺序和随机结果采用适合问题的等价或统计判据。

误差预算须有依据或标为待确定，不能看见待验答案后放宽。比较器应能拒绝本题相关的常见错误，如单位、符号、轴序、零输出、错分支或硬编码样例；经过某模块不等于验证其能力。论文提供解释和场景，论文有而绑定源码没有的能力不能算来源已经支持。

按 [案例包约定](references/case-contract.md) 在项目的 `case/<中文题目>` 一题一根保存，根下仅 `题面/`、`参考/` 两个目录和小入口文件。题面包含完整语义、全部输入、输出与公开规则；参考包含结果、比较器、合法源码/许可及题内运行配方/依赖锁。不得依赖另一题或散落的会话路径，不维护第二套题意。出库执行可另按任务要求记录实际消费库能力调用及补充科学计算，但不能让这些已有能力反向决定题库范围。

## 来源复现与运行收尾

在本任务已有授权内运行源码；本 skill 不新增下载、构建、运行或外部写入权限，也不要求对已有授权重复确认。使用绑定来源的真实入口与完整输入，保留版本、环境/镜像身份、命令、原始输出、退出码和适用数值配置。任何源码修补都必须披露并绑定，不能悄悄修改科学行为使题目可跑。

任务已授权下载环境依赖时，直接取得并在任务规定的隔离环境中安装、验证和锁定版本；尚未尝试取得普通依赖不算外部阻塞。需要现有授权凭据、受限资产或尚未取得的软件使用权时，记录实际缺口。环境可用性以真实获取、构建或运行结果为据。

需求题面交付与参考复现分别判断。来源构建、运行或收敛失败时，保留可独立理解的完整题面、来源锚点和实际失败证据，明确参考结果尚未取得；在用户允许先交题目的任务中，不以修复来源或反复运行作为题面交付前置。若目标、物理约定或必需输入仍不清楚，继续标为题意待澄清，不能把范围草案计作已交付题目。

来源输出证明该版本的行为，不能自动升级为物理真值。算法、直接数值测试和科学正确性的审查交给指定人工/科学审阅者；本方法不批准能力、不恢复拆解流水线、不执行接收入库。

需要容器时先核实后端、存储和资源，优先复用符合项目合同的环境。每题保留可复建配方、依赖锁、环境身份及从题根定位的重放入口；OCI 镜像/工具/系统库可显式外置，不把大镜像复制进每题。历史 source-run argv 保留原文；封装后另从题根实际重放，不能篡改历史充当新证据。运行结束或失败后停止本任务启动的容器并核对退出；保留有复用用途的镜像/定义及必要恢复材料，不停止其他任务容器或共享引擎。结束的临时材料使用本机既有安全删除流程清理。

## 交付与自检

交付能力清单、候选题/可复现题包、参考复现材料、覆盖和缺口报告；明确 `NOT_RUN`、`HOLD`、待人工审查与已冻结的区别。未出题或未跑通的能力继续留在覆盖分母里。不得仅由题数、参数变体或自动脚本宣布全覆盖。

按交付范围选择校验，完整题面做普通校验，参考复现包另加严格检查：

```text
python scripts/validate_package.py <case-root>
python scripts/validate_package.py <case-root> --require-reference
```

校验器检查所声明的题内材料闭包、路径边界和记录一致性；`reference-reproduced` 要求题内源码、配方/锁及真实封装重放，缺口在候选的 `HOLD` 中明确。`PASS` 不代表科学审查通过，也不执行脚本证明全部动态依赖。

仅题面交付的包使用普通校验并保持 `candidate`，在题内明确题面完成范围与参考缺口；只有取得真实来源与题根重放后才做相应参考状态升级。人工科学审查 pending 与工程复现是否发生是两件事，不能仅据前者把已经发生的来源执行写为未运行。
