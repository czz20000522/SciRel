# 能力覆盖与工作量估算

先建立候选能力清单，再选题。将源码入口/实现分区与文档、论文、已有案例各自列出的能力交叉核对，记录来源锚点，避免从同一份遗漏清单同时生成题目和“100% 覆盖”。

能力按科学任务、模型和输入输出关系划分。一个 API 可能包含多项能力，一项能力也可能跨多个函数。必要的物理区间、几何、边界、退化情况和关键组合单独列为覆盖条件；不把每个参数值或无依据的全笛卡尔积当成新能力。库中的数值工具只有在承载明确科学任务时才进入分母，纯 IO、绘图和包装排除并给理由。

建议每行记录：稳定能力 ID、科学任务与范围、源码/文档锚点、必要条件、候选题、有效判定点、当前证据状态、缺口或排除理由。清单格式可沿项目已有入口。

- 能力分母：本次盘点出的全部范围内科学能力，包含未出题、运行受阻和待澄清项。
- 能力分子：被题目实际触发，且有对该能力敏感的有效判据检验的部分。
- 条件覆盖：另报必要工况/边界覆盖，保留未覆盖清单，不用一个总分掩盖关键空白。
- 一个题目可以覆盖多行，一行可以需要多题；覆盖关联必须说明观测量及判定，不能只写“调用经过”。

需求提供覆盖与参考验证覆盖分别报告：完整题目已覆盖的物理目标可记为需求已提供；来源运行失败、但题面完整的项目仍可先交需求，参考验证分子保持未覆盖。题意不全的旧范围卡、缺少模型或输入的草案均不算完整题。不能用来源失败删除能力分母，也不能用题面交付冒充参考复现。

盘点存在不确定性时给上下界或“已识别/待确认”数，不捏造精确总数。问题切分以可独立解释和判断的物理目标为准，不固定每函数一题，也不强制每题大型端到端。

## 估时

分别估计以下成本：

1. 来源与文献定位、能力盘点；
2. 中立题意、输入和输出约定整理；
3. 环境冷启动/构建与复用后的每次运行；
4. 来源参考捕获、输出语义转换与复现；
5. 比较规则、误差依据、错误样例与覆盖材料；
6. 指定人工的科学审查（没有实际信息时不估作已包含）。

用一两道代表题实测墙钟时间、计算耗时和 Agent 工作量，再外推。给数量区间、可并行部分、共享环境成本、串行瓶颈和主要未知，避免把总人时直接当墙钟时间。大任务先交预览：优先选源码入口清楚且覆盖不同能力族的少量题；若只有一个能力族，可选有不同判定点的正常与边界任务并说明关系。

运行受阻或科学定义未闭合时保留候选与阻塞原因。不得因当前消费库不支持、暂时跑不通或进度慢而从清单删能力，也不把题目生成完成写成参考复现或科学验收完成。

用户接受来源失败后先交题目时，需求交付估时不再包含来源科学代码修复或无变化重跑。另列可下载依赖的获取/安装成本、可继续的参考捕获，以及需要外部材料或题意澄清的项；科学定义不清的题目仍需估计整理工作，不能自动视为已完成。
