# Scientific skill group stage boundary contract

These D0/D1/D2/D3 methods apply across scientific disciplines, library names, languages and Agent harnesses.
The project owns scientific meaning and stage acceptance; the selected harness supplies execution and delegation.
A package name, job state, container name or tool result never substitutes for scientific qualification.

The run configuration supplies the available runtime/container backend, source and result locations, resources,
dependencies, Agent/model settings and permitted delegation. Inspect the actual platform and prepare dependencies
inside its independent isolation boundary; verify read-only upstream, phase-specific source writes and persistent outputs before execution.
Use a project-native private area for generated code, probes, builds and evidence. Local devices, cloud servers
and heterogeneous clusters may implement this boundary differently. Do not fix one device path, Agent framework,
subagent type, package name or deployment backend in the scientific method.

This reference supplies the self-contained extraction boundary. Later-stage implementation adapters, submission
APIs and release policy are supplied by the receiving project; they are not prerequisites to D1. The method hands
off exact artifacts and claims without loading an unavailable repository or duplicating downstream policy.
Bundled validators and schema namespaces are optional versioned serialization implementations: use their real
contract when selected, or an equivalent project protocol carrying the same scientific information. Their filenames
or schema prefix do not require a library of that name. A structural pass never substitutes for scientific evidence.

## D0 responsibility

D0 owns authorized source preparation in an editable branch/copy of read-only official upstream. It may remove
unfinished or clearly faulty paths and make evidenced cleanup changes, recording upstream identity, the exact delta,
rationale, retained scope and unresolved limits. It prepares reusable AOCI/CodeGraph views and a reconstructible
environment, then freezes a shareable D0. See [D0 preparation](material_access_and_preprocessing.md#d0-source-preparation).
This is a transparent derived version, not scientific endorsement or a per-item approval process.

In D1 and its specialists, bound/original source means that frozen D0. D1 must cover its entire retained scope;
it does not repeat D0 scope decisions or claim fidelity to all unchanged official upstream. Both upstream and D0
identities and their differences remain traceable. A source change after freeze requires a successor, not a rewrite.

## D1 responsibility

D1 acceptance is `source_fidelity`: reproduce the existing behavior of the bound source, including its
defaults, numerical choices, state/order, terminal outputs and reproducible failures. The source implementation
is the behavioral oracle; D1 does not certify its scientific or numerical correctness. Record suspected source
defects for D2 instead of repairing them or opening independent physics/calibration research. Fix introduced
extraction, packaging and comparison errors within D1. This boundary governs every specialist and linked
reference loaded by D1; scientific-correction and independent-science instructions apply to a later explicitly
scoped correctness task.

Prefer lifting or wrapping actual source logic over deriving a new algorithm. A Python callable may use
attributable packaged Python, C/C++, Fortran, local binaries or declared native dependencies. `source-free`
means independence from the original checkout/environment, not absence of source-derived implementation.
Retain licenses, build recipes, compiler/dependency identities, ABI/platform support, explicit state ownership,
initialization/reset and failure mappings. Internal native state may remain encapsulated when its lifecycle and
isolation are explicit; do not require a new carrier for every internal temporary. A whole-program wrapper may
establish an initial comparison path, but does not replace source-supported reusable mappings and composition.

Use original examples and self-constructed source-admissible inputs for differential tests of outputs,
state transitions, branches and failures. Retain raw source/candidate observations and fixed comparison rules;
reuse valid evidence. Extend cases for material uncovered behavior, not an unlimited input universe. Independent
physical oracles, analytical correctness, convergence proofs, experimental calibration and statistically
independent holdouts are not default D1 gates. A fixed-input source need not invent another admissible input.
Never tune tolerances to candidate output, substitute captured answers for computation, or assert equivalence
of undefined behavior. Missing comparison evidence remains a fidelity gap.

Record a source issue once in existing code/evidence: source identity/location, triggering inputs/state,
observed behavior, affected scope and reproduction evidence; distinguish suspicion from demonstrated fact.
Variants still needed by the current task and their evidence remain separate later-stage candidates; do not
substitute them for the faithful version. Reproducing a known source error can pass the corresponding fidelity
check while remaining unqualified for scientific use. Full D1 completion requires all declared source functions,
material branches and dependencies accounted for, attributable comparison and source-free reassembly, plus
read-only fidelity/completeness review where required by the caller. It is not scientific endorsement.

D1 produces a saved, source-traceable L1 bundle: complete source coverage, source-shaped callable code,
TaskGraph structure, necessary scientific anchors, tests, evidence, provenance, and explicit gaps. The result remains a
re-runnable source candidate. It is not a normalized maintained-library identity, an expert decision, a maintained-baseline
change, a catalog entry, or a release.

Keep the output source-shaped and preserve its lineage. Do not perform cross-project equivalence decisions,
deduplication, public namespace design, expert approval, or release work. Those exclusions do not make imperfect L1
material invalid by definition: record recoverable format, test, evidence, and scientific gaps with enough detail for
a later integration workflow to diagnose them without rewriting the saved source record.

## D2 and D3 responsibilities

D2 compares a saved project delivery against the receiving library's current scientific baseline, accounts for every
input, deduplicates or preserves justified variants, integrates and validates retained capabilities, and supplies an
exact runnable development distribution with its actual discovery surface. Wheel/catalog is one Python deployment
form, not a required package name, language or transport. Prepare one concise canonical scientific document for each
stable retained capability; code, tests and evidence are optional drill-down maintained consistently by the Agent.

D2 consumes upstream-to-D0 lineage and every D1 source-issue record and decides correction, explicitly retained compatibility variant,
exclusion or unresolved limitation with evidence. It owns scientific-relation/numerical correctness testing for
the retained claims. Corrections preserve failure regressions, intentional source divergence and affected
dependency validation. D0 preparation does not discharge D2 correctness duties; D2 works in its own derived candidate
without reopening the frozen D0 scope. D1 parity is reusable evidence, not independent scientific acceptance.

Apply the receiving project's admission policy to the actual retained contract and runtime dependency closure.
An unresolved issue can remain in the project handoff without entering its accepted scientific distribution;
a pending human-review label does not establish correctness. Supported but incomplete scope and contradictory
evidence are different cases. See [evidence-based review attention](../../scientific-operator-review/references/evidence_based_review_attention.md)
for meaningful restrictions, multiple AI review rounds and human attention allocation. A compatibility candidate
is not automatically eligible for packaging merely because it reproduces the source.

D3 consumes that exact delivery to complete useful user tasks, checks actual inputs, applicability, port connections,
results and failure recovery, and supplies a runnable application plus independent reproduction evidence. It does
not repeat valid source comparisons or create an application per operator. Separate stage owners may resume weeks
later from durable artifacts. Independent review, human endorsement and publication remain distinct decisions.

## Information and immutable handoff

A scientific contract is not a mandatory Markdown file. D1 anchors it in delivered code, YAML, docstrings,
function/module comments and existing scientific records. Reference recoverable facts there; state necessary
nonrecoverable units, assumptions, conventions, provenance and validation basis once. Minimal information does
not mean creating another draft Markdown page. Code comments may retain source references, implementation
conventions and internal details that do not belong in the formal human-facing document.

D2 reads the delivered D1 snapshot without changing it. Deduplication decisions, corrections, annotations and
new tests belong to D2's derived candidate, with a link to the original. The same read-only input rule applies
between every stage. A successor never rewrites a prior stage's frozen claims or evidence.

The default D1 handoff unit is the frozen D0 project, after pursuing its whole-source extraction and validation.
Ready relations and graphs advance D1 internally; they do not automatically launch downstream stages. Preserve
unfinished scope and blockers explicitly, and never shrink the declared scope to claim project completion.
An explicitly agreed bounded pilot/partial intake may transfer qualified material under its narrower ceiling.

A receiving owner may start weeks later with no access to the original Agent, chat or temporary environment.
Provide one compact continuation entry using the existing project records: exact upstream and D0 identities/license/delta,
whole-project census and asset/dependency dispositions, unresolved scope, callable bundle identity, source inputs,
raw observations and criteria/evidence bindings, and pinned runtime dependencies with reconstruction/rerun commands.
All cited artifacts must remain obtainable with the saved delivery. Keep upstream and D0 snapshots and raw evidence in
the associated archive outside the callable package; attributable extracted runtime implementation may be packaged.
Do not duplicate archives into every asset or create
another scientific report. A saved incomplete project remains incomplete. Age or owner replacement alone does
not invalidate attributable numerical evidence; later comparison uses the receiving stage's current library baseline.

Formal operator/TaskGraph documents are generated only after D2 comparison, deduplication, correction and
assembly stabilize the retained new/changed code, before final review freeze. Duplicate or covered assets need
attributable disposition and scientific comparison evidence, not duplicate formal pages. Partial overlap alone
is not equivalence. Human approval decides the final frozen review version; intermediate Agent review and
internal development assembly do not require a human decision and do not imply publication.

## Scientific and mechanical completion

D1 must establish complete declared-source coverage, source-shaped implementations, and numerical comparisons
with the source before a qualified complete L1 `full_freeze`. Later stages may not be able to access or run the
source, so unresolved source-behavior coverage or comparison remains a named D1 gap. An incomplete candidate may be
saved under an explicit claim ceiling but must not be reported as qualified complete material.

When an executed result still has independently verifiable code, inputs, outputs, and runtime-relevant
conditions, fix a path, assertion, format, or digest binding with a traceable supplemental record instead of
repeating the calculation. Check an assertion against source semantics and independent results; do not relax
its comparison tolerance to fit the candidate. D1 uses source behavior as the expected result; independent
scientific criteria belong to a correctness claim. Preserve the old failure and its evidence, without fabricating
a historical seal. Rerun only the affected cheap comparison or gate; repeat scientific execution when its
correspondence is missing or the inputs, executable science, or environment materially changed.

For a `bounded_delivery` handoff, D1 requires an independent read-only Agent review of the exact source-derived
census, selected bundle assets, reassembly evidence, and deferred capability register. The review receipt is a finite
exit decision for that batch, not expert approval and not a `full_freeze` claim. The producing coordinator must not
also act as this reviewer, and the reviewer must not edit the bundle or progress snapshot.
An authorized separate visible thread is a valid independent context. Use `reviewer_role=independent_agent` for it;
the validator also accepts the historical `independent_subagent` role without rewriting old receipts. Record actual
reviewer identity, harness/model version and reviewed scope in the existing review evidence. The role string alone
does not prove independence. A workflow does not require a hidden child agent, and caller delegation rules apply.

## Preserved material and gaps

- Preserve the source snapshot, raw evidence, L1 bundle, and their content identities.
- Record a gap with the observed fact, evidence, affected claim, next evidence or decision needed, and the condition
  that would make it actionable.
- Keep tool failures distinct from scientific defects. Missing evidence caps the claim and need not block unrelated
  candidates.
- Do not infer approval, publication, or maintained-baseline membership from a candidate, test result, review note,
  staged digest, or `full_freeze` signal.

These retention rules support the active delivery. An explicit user-authorized reset may clear old work without
backup while preserving designated sources, tools and credentials. Do not force preservation of retired runs or
reuse their frozen claims for a new version; retain learned methods separately.

Use content digests where bytes cross an artifact or evidence boundary. Do not create per-edit digest ceremony for
ordinary working notes.

## TaskGraph and evidence constraints

Optional serialization validators retain their exact contracts when selected. Their legacy fields or sealed-case
requirements do not add scientific-correctness duties to D1. Use the caller's source-fidelity evidence protocol
when those extra claims are not requested; do not fabricate seals, rewrite old receipts or claim that an unchanged
validator passed a new protocol. Completion reports name the actual protocol and exact evidence reviewed.

Ordinary TaskGraphs are dependency-closed DAGs. Feedback or iteration must declare state, update order, stopping
condition, finite bound, and nonconvergence behavior. Source parity proves source behavior only; it does not prove
general physical correctness. Project examples may support a bounded claim but do not automatically become global
rules for every scientific asset.

For a D1 full-freeze claim, the extraction gate derives `closure_signal.kind=full_freeze` from the declared scope,
resolved asset references, package tests, source-free execution, and required reassembly evidence. This signal means
only that the declared L1 extraction bundle is internally frozen; it does not approve or publish the candidates. A
model must not set it merely because its own run completed.
