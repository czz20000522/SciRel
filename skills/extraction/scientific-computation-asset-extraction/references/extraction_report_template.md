# Project Extraction Handoff

Use this reference at a whole-project or explicitly bounded handoff. During production, retain only the existing
scientific census, exact evidence locators and resumable private notes needed to continue. Do not generate and
synchronize several narrative tables after every implementation edit.

The [intake directory contract](intake_directory_contract.md) retains the existing root files for compatibility.
Their scientific content matters; heading order, prose language, diagram appearance and repeated counts do not.
These records do not replace callable code, source comparisons or independent scientific review.

## Root records and ownership

| Existing record | Responsibility | Avoid duplicating |
| --- | --- | --- |
| `program_framework_map.md` | Source scope and relations; operators, local graph subwebs, important state/port edges and uncovered science | Full code/port tables already available in code, graph YAML or the scientific census |
| `extraction_report.md` | Concise final delivered scope, exact evidence snapshot, claim ceiling and remaining risks | Per-candidate history, raw logs and every numerical output |
| `extraction_ledger.md` | Candidate/disposition decisions, source locators, genuine gaps and evidence links | Canonical scientific facts already anchored in code or YAML |

Each fact has one maintained home. Root records may link to exact existing records instead of restating them.
A minimal scientific anchor may be a function/module comment; it need not be another draft Markdown file.
A source/evidence file needed by the next stage must be retained or included as a frozen attachment. A path to a
discarded scratch file is not a handoff.

The upstream bundle is read-only after handoff. A later stage writes comparison decisions, annotations,
corrections and successor claims only in its derived candidate, retaining the original source/bundle identity.

## Required handoff facts

- Exact source universe and preserved source snapshot, including excluded partitions and their evidence.
- The complete source-derived candidate/disposition map for the declared claim: formulas, meaningful operators,
  ordered graph relations, material branches, state lifecycles and terminal paths cannot disappear.
- Delivered package locations and dependency bindings, with source mapping and semantic-anchor locators.
- Actual implementation/source comparison, numerical validation and source-free reassembly evidence: exact
  inputs, outputs, oracle, metrics/tolerances, runtime conditions and limitations. Refer to bound records.
- Current validated progress snapshot and `closure_signal`, plus review receipt where that boundary requires one.
- Unfinished scientific frontier, affected claims and concrete reopen conditions. Separate mechanical repair
  from missing science, source defects and genuine external dependencies.

For `bounded_delivery`, name exactly the delivered targets, canonical/sealed-holdout evidence and the independent
read-only review receipt. Keep deferred source capabilities as locators with dispositions and reopen conditions;
do not emit placeholder assets or add them to a later human review queue. Bounded delivery is not full completion.
For `full_freeze`, the complete declared source census and all required target paths/scientific checks must close;
package counts, polished prose or a passing structural check are not substitutes.

## Optional projections

A physical overview or Mermaid diagram can help a human understand the final project map. Derive it from existing
scientific records when useful; do not create a second manually maintained truth. Use
[source framework production](source_framework_production_manual.md) for a difficult source/state map,
[physics framework production](physics_framework_production_manual.md) for a physical overview, and
the capability closure and progress record for actual completion evidence.
A dense hidden-state slice may have a separate map only when it has a current consumer; otherwise reference code,
YAML and the existing state records.

Formal operator/TaskGraph or exact scientific asset documents are produced after D2 deduplication/correction/assembly,
only for retained new/changed assets before final review freeze. The root handoff is not a substitute for that
later document and is not a reason to generate it prematurely.
