# 测试与证据

测试的作用有两个：证明这个关系是对的，并且在以后被修改时能被抓住。合并线会用变异测试检查你的测试：把单位改错一个数量级、把符号取反、交换轴序、把输出置零、换成硬编码的样例值，这些错误版本都必须被你的测试判红。

## 1. 测试矩阵

每个关系至少要有：

| 类别 | 要测什么 |
| --- | --- |
| 正常 | 典型参数下的值 |
| 下界、上界 | 适用范围两端的值；超出范围时的报错或警告（`ApplicabilityWarning` 由 #156 实现后改用它） |
| 退化（适用时） | 参数趋于 0 或无穷、对称情形 |
| 分支（适用时） | 每个 `method`、每条条件分支 |
| 失败（适用时） | 非法输入的报错消息要包含参数名和合法范围 |
| 终止（迭代类） | 收敛、达到迭代上限、发散；不收敛时的返回值不能看起来像收敛了 |
| 组合（适用时） | 与上下游关系连起来时，单位和形状是否衔接 |

一个测试只断言一件事。断言消息写判据，而不是复述数值，例如"远场应趋于偶极 1/r^3 衰减"，而不是"应等于 0.0123"。

## 2. 预期值的依据

优先顺序如下：

1. **解析**：极限、对称性、可以手算的特例。推导写进 `evidence/`。
2. **文献**：表值、图中读数、公式的数值例。写明作者、年份、表号或式号。可以联网检索。
3. **守恒**：粒子数、能量、动量、通量守恒，或者积分恒等式。
4. **来源输出**：与来源在同一组输入上对照。它只能证明"和来源一样"，不能证明"物理上正确"。

一个关系如果只有第 4 类依据，在 `evidence/` 里标"仅来源对照"。合并线会把它归为 B 级以下的待补证据项。

## 3. 容差

- 容差要有理由：浮点精度、拟合声明的精度、文献的有效位数、数值方法的收敛阶。理由写进 `evidence/`。
- 不能先看实现的输出再定容差，不能为了通过而放宽容差，也不能删除失败的用例。

## 4. 物理纠正

发现来源实现在物理上有问题时：

1. 先排除"有意的近似或约定"：查来源的注释、文档、配套论文，确认它是否声明过这个近似。
2. 有独立依据证明它是错的，就实现正确版本，并在 `evidence/` 写清：
   - 原行为（同一输入下来源给出的值）；
   - 依据（文献或推导）；
   - 改动内容；
   - 前后对比。
3. 没有依据，就照来源实现，在合同的局限性里写明疑点。影响面大的（会让结果在没有任何迹象的情况下出错），开工单。

## 5. 来源行为里值得保留的部分

和来源对照时，下面这些也要对照，不能只比主输出：

- 终止语义：正常返回、迭代上限、阈值判断是在状态更新之前还是之后、失败标记；
- 分支选择：不同输入会走哪条分支；
- 非有限值：来源在什么输入下产生 NaN 或 inf，SciReL 版本在同样输入下应当报错。
