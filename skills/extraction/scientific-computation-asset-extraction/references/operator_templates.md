# Scientific Anchor and Documentation Routing

## D1 最小科学锚点

D1 不生成正式 `operator.md` 或 `task_graph.md`。必要信息可以分布在交付代码、YAML、docstring 和已有科学记录中；
为消费者提供精确定位即可，不复制一份接口表、另一份审核页再附同内容摘要。

科学信息仍须明确：关系定义、真实输入输出、单位/归一化、shape/轴序、适用条件、边界与失败行为、来源位置、
图中状态和有序关系，以及实现/数值对照依据。代码可以可靠表达的事实从代码读取；代码无法唯一表达的物理约定、
假设、单位和来源语义就地补充。不能把未知含义藏在变量名、`source-unit`、通用占位句或“以后审核”后面。

真正缺失的科学语义、来源或验证仍是 D1 缺口；页面缺失、语言、标题顺序和模板格式不是。

## D2 稳定后生成正式文档

接收端 D2 owner 完成与已有资产的比较、去重、修改和组装；稳定后按接收项目提供的科学文档合同
为保留的新/变资产生成唯一 canonical exact document，不要求特定库名、仓库文档路径或提交工具。
这些是后续阶段的入口和合同，不随 D1 五技能包部署；D1 无需加载它们或因其不可见而等待。
正式文档在最终审核冻结前验证它与确切代码、端口和证据一致。重复或被涵盖的资产保留 disposition、来源和等价证据即可；
局部重叠不自动等价。不同稳定资产可以并行撰写，保持一个整合写者。

现有模板和参考案例仅是可借用的表达样例；不要求先生成 L1 Markdown 再重写为库文档。正式文档应先说明
科学关系、假设、量和适用边界，再表达调用合同与证据限制，不逐行翻译实现。一次信息只维护一个权威表达。
人类读取最终冻结版本并拍板；文档撰写和日常科学修复无需等人类中间裁决。

## 证据表达

可执行测试保留预先确定的 oracle、指标、容差、输入和预期行为。实际运行记录保留命令、代码/来源身份、环境、
完整输出和每项重要结果的数值度量。记录可以是测试内注释或已有绑定证据，不强制中文测试头、标签顺序或每段注释。
编译成功、可导入和固定格式均不能代替数值验证。

运行结果归属可独立证明时，修正文档/路径/包装绑定只重跑受影响的廉价检查，复用原科学结果；来源、科学代码、
输入或相关环境改变时，验证受影响范围。不得为通过检查修改物理含义或放宽容差。
