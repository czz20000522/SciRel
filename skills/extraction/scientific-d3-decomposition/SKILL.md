# Scientific D3 decomposition

Read [the standalone decomposition contract](../scientific-computation-asset-extraction/references/scirel-skill-core.md).
For the packet shape, load [D3 observation packet](references/d3-observation-packet.md).
This stage produces application evidence that a downstream developer or
reviewer can consume. It does not import development skills, mutate a user
project, approve an asset, or publish a package.

1. Bind the exact D2 candidate/catalog, dependency/runtime profile, normalized
   application case, inputs/outputs, supported platform and evidence scope.
   Keep the full declared case/branch/failure denominator.
2. Execute the smallest authorized application matrix that distinguishes
   applicability, ports/units/axes, boundaries, convergence, bad input,
   recovery and ordinary repeatability. Record exact command, runtime identity,
   output hashes and failures.
3. Read outputs independently through the consumer path. Keep computed
   observations separate from physical interpretation, library correctness,
   human endorsement, rights and release.
4. Return a digest-bound D3 observation packet with cases by state, result
   hashes, gaps, `NOT_RUN` scope, claim ceiling, and next developer owner. One
   successful case does not qualify the library or package.
