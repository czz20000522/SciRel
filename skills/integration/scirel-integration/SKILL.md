# Scientific Asset Integration

Own D2 comparison, deduplication, repair, composition and development delivery.
Own scientific-relation and numerical-method correctness for retained claims. D1 establishes source fidelity,
including original errors, and supplies source-issue records; it does not owe corrected behavior or independent
physical qualification. Consume each issue with an evidenced correction, explicit compatibility variant,
exclusion or unresolved limitation. Do not return a source defect to D1 merely to make its faithful output
scientifically correct. Packaging/extraction mismatches may return as specific fidelity questions.
For a confirmed defect within the authorized D2 scope, initiate the existing
[scientific-correction workflow](../../extraction/scientific-relation-implementation/references/scientific-correction.md):
diagnose from the source observation and independent scientific basis, implement a corrected successor through
`scientific-relation-implementation`, obtain independent `scientific-computation-validation` evidence, and
submit that revision to `scientific-operator-review`. Isolation protects the package while this work proceeds;
it is not the default final disposition of a repairable defect. Do not replace implementation with a warning,
scope reduction or request for a human to write the fix. D2 repair authority already covers this work; no
per-defect approval is needed within that scope. Temporary runtime/resource failure leaves repair pending.
Defer scientific repair only after necessary investigation cannot determine the behavior or a justified remedy;
record attempts, the precise missing fact, impact and reopening condition. A complete disposition list alone
does not establish completed remediation. Final review consumes corrected, validated code and its before/after
explanation, not merely a list of discovered defects. Follow that protocol's disclosure instead of duplicating it.
Apply the receiving project's internal-package admission policy before retaining those variants or limitations:
a pending-review label is not permission to ship unresolved incorrect behavior. For supported restricted claims,
isolation of faulty scopes and differentiated review effort, use
[evidence-based review attention](../../extraction/scientific-operator-review/references/evidence_based_review_attention.md).
Retain packaged native implementations when appropriate; Python public callables do not require Python-only
internals. Verify their source/permission, build/ABI, dependency and state/exception contracts.
Use the portable [stage boundaries](../../extraction/scientific-computation-asset-extraction/references/stage_boundary_contract.md).
The current discovery identifier is retained for compatibility; it does not require that library or package name.
The receiving project supplies its lifecycle policy, runtime, source/result locations, baseline and distribution format.
No particular Agent harness, device, container backend or subagent model is required.

## Start and route

Normally receive a saved source-project D1 delivery, not a stream of individual ready operators/graphs.
The producer may have finished weeks earlier; use its durable entry and artifacts, not its chat or live environment.
Check the project's coverage, asset/dependency dispositions, evidence and explicit gaps; an incomplete saved project
is not full D1 completion. Only an explicitly agreed bounded pilot/partial intake changes the default intake scope.
Read exact L1 inputs and scope/evidence, the receiving stage's current development Git base, previous trusted version if any,
and relevant unpublished candidates. Discover only affected scientific families.
For D2 comparison inspect relevant maintained source, public exports, tests and unpublished work directly;
catalog absence is not library absence. The navigation specialist below is limited to cataloged capabilities
and cannot discover retained development code whose formal document is still deferred.
Keep inputs and frozen versions read-only; develop in the owned isolated branch. Development packages may run before approval.

| Need | Conditional route |
| --- | --- |
| Find existing cataloged capabilities | [scientific-asset-navigation](../../usage/scientific-asset-navigation/SKILL.md) |
| Compare, deduplicate, retain variants, adapt or compose | [scientific-asset-normalization](../scientific-asset-normalization/SKILL.md) |
| Concrete contradiction or bounded scientific repair | [scientific-asset-correctness](../scientific-asset-correctness/SKILL.md) |
| Missing independent numerical evidence | [scientific-computation-validation](../../extraction/scientific-computation-validation/SKILL.md) |
| Stable retained assets need formal documents | [canonical document preparation](../scientific-asset-normalization/references/relation-page-contract.md) |
| Stable cumulative increment ready for final review | [scirel-review-preparation](../scirel-review-preparation/SKILL.md) |

These are conditional routes, not mandatory sequential audits. Reuse attributable D1 evidence.
Missing Markdown or a repairable packaging reference does not require another source computation.

## Coordinate and integrate

Account for every input once with disposition, target, source lineage and evidence.
Annotate this stage's derived code with source references, absorption decisions and implementation conventions
using comments/docstrings or existing task records. Do not annotate upstream deliveries or copy internal notes
into human-facing standardized review documents.
Compare meaning, units, assumptions, domain, state and numerical behavior; names/hashes/sample outputs only shortlist.
A larger graph or partial overlap does not automatically absorb an independent contract.
When API names differ, bind scientific ports before treating direct-test failure as semantic conflict.

Partition independent families among available workers with private outputs and one integration writer.
Fix justified changes; revalidate affected assets and reverse dependencies. Preserve disjoint work and frozen evidence.
Missing science blocks that claim; route source-specific uncertainty to D1 with the smallest question.
Agent investigation handles intermediate choices within authorization.

Generate formal exact documents after comparison and stable code, only for retained new/changed assets.
Reused assets keep existing documents; absorbed inputs need disposition/provenance, not duplicate review items.
Code/YAML/tests carry recoverable detail until documentation. Build and test a clearly identified development
distribution and matching discovery records when D3 needs them; tests grant no approval.
Before packaging, verify the selected runtime and transitive dependencies actually implement only admissible
claims; warnings, private naming and catalog omission do not exclude executable faulty paths. Keep unsupported
research candidates outside the accepted runtime. Claim restrictions must be meaningful and visible in the API
contract/docstrings, not selected merely to remove a failed fixture.

## Handoff

Deliver development SHA, complete dispositions, scientific changes, affected tests, actual distribution/discovery records,
supported scope and gaps. Submit focused commits for integration. D3 may consume the development version.
Stage owners and handoff times are independent; no live D1 Agent or same-night full chain is required.
When the caller authorizes whole-project delivery, use that independence for durable recovery, not default delay.
Before freeze, prepare the receiver's environment, independent checks and integration target from existing scope
records; do not accept mutable bytes or retain a waiting reviewer. On observing a new frozen delivery, prioritize
its reception and authorized continuation in the current executable work period. Preserve the complete core-task
denominator through corrections, installed application validation, package integration and document synchronization.
Record an actual blocker, next owner/action and reopening condition when continuation cannot proceed. Reuse valid
evidence and measure freeze-to-reception waiting separately from scientific execution; unknown timing stays unknown.
Select useful D3 tasks over the integrated capability set, not one new application per input asset.
Route final review only when the retained increment is stable, not for each interim revision.
