# 求解流程框架

用户问题无法枚举，所以这里约束的是过程，不是题型。每个任务都走同样五个阶段，每个阶段有产物和进入下一阶段的条件。分支在阶段内部处理。

```text
需求澄清 → 物理建模与方法设计 → 用户确认 → 计算与验证 → 带图的报告
   ↑                               │
   └───── 物理前提变了就退回 ──────┘
```

| 阶段 | 产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1 需求澄清 | `request.md`：用户原话、已确认口径、仍未知的量 | 剩下的未知量不再改变计算结果 |
| 2 物理建模与方法设计 | `method.md`：[物理方法](method-design.md) | 物理链条从问题到结果没有断点 |
| 3 用户确认 | 用户对方法的确认或修改 | 用户确认，或任务明确授权跳过 |
| 4 计算与验证 | 程序、`data/`、`data/checks.json` | [结果检查](result-checks.md)已运行，失败已保留 |
| 5 报告 | `REPORT.md`、`figures/`，见[报告格式](report-format.md) | 报告校验通过，图已逐张看过 |

## 阶段 1：需求澄清

重述问题，并判断属于哪类问题。只追问会改变计算或结论的内容，一次一到三个问题，先问影响最大的。详见[澄清方法](clarification.md)。

**何时结束：** 模型、几何、输入、输出量的定义和符号约定都已确定，同一份口径交给另一个人会算出同样的数。还不知道的量如果不影响计算（例如用户的容许指标），就记下来，不必继续追问。用户给不出的量，保留为未知，并给出条件结果。

## 阶段 2：物理建模与方法设计

先写物理，再想代码。方法要让懂物理、不一定懂代码的读者能跟下来。

需要用到现成算子时再去[检索 SciRel](capability-discovery.md)。检索是为了省事和复用已验证的实现，不是流程目标。

## 阶段 3：用户确认

把物理假设和方法用几句话给用户看。确认的重点是模型是否符合用户的物理情况。不要把内部实现细节交给用户确认。

如果用户已明确说不用确认，或在这一阶段前已经确认了全部物理口径，可以直接继续，并在 `method.md` 里写明。

平台不支持中途提问时，把假设写清楚并继续，在报告的“问题与理解”里标明这些假设未经确认。

## 阶段 4：计算与验证

按方法实现。原始精度的数字都写入 `data/`，之后的步骤只从保存的文件读回。

检查要能分辨符号、归一化、单位这类看似合理的错误。容差在看结果之前定好。核对失败时先查原因；如果是核对方法本身的问题，改进方法并说明，不要放宽容差。失败和未运行的内容如实写进报告。

## 阶段 5：报告

报告是一篇短论文：答案 → 问题与理解 → 物理模型与方法 → 结果与图 → 讨论 → 结论 → 附录。格式和校验见[报告格式](report-format.md)。

## 分支

| 情况 | 怎么处理 |
| --- | --- |
| 不需要数值计算（定义、公式推导、量级估计、概念问题） | 仍要澄清和写出物理推理；可用解析结果或估算回答，跳过阶段 4 的程序，报告可以很短。不要为了走流程硬写程序 |
| SciRel 有合适的算子 | 读完整合同，确认单位、符号和适用范围后使用，在方法里顺带注明一句 |
| SciRel 没有，或不完全匹配 | 用 NumPy、SciPy 或自己写的代码，这很常见。写清楚公式和假设并加以验证，见[补充计算](glue-gap.md) |
| 物理假设在计算中被推翻 | 退回阶段 2，告诉用户变化，不要静默修改模型 |
| 澄清不能收敛（用户给不出关键量） | 用明确的条件分支计算，或说明缺什么；不要自己编一个值 |
| 涉及参数扫描 | 在方法里说明扫描的物理目的和范围，输出用曲线或等值线图；区间外不外推 |
| 涉及优化或设计 | 目标函数和约束必须来自用户，写进 `request.md`；用户没给就先澄清，不要自创目标或权重 |
| 需要用户数据 | 先检查单位、覆盖范围和坏点；对数据的处理写进方法 |
| 需要判定是否合格 | 只有用户给了判据才判定；没有判据时讲清楚变化，并说明用户可以怎样对照自己的要求 |
| 计算失败或不收敛 | 这是结果的一部分。如实报告，并说明已完成的部分和下一步需要什么 |

内部评测（SciRel 维护者测试包本身）还要多做一步：发现公开能力缺口时写[缺口卡](capability-gap-intake.md)。这不改变以上流程。

## 可视化

凡是结果涉及空间分布、函数关系或多个工况比较的，都要画图。标量答案或概念问题可以不画，并写明原因。

每张图只回答一个问题。绘图通常用 matplotlib。它只用于报告，不是 SciRel 包的依赖，任务环境里没有时单独安装（`python -m pip install matplotlib`）。稠密网格的图只用于观察，指标仍然按用户定义的点计算，并在图注中说明。图生成后要打开检查文字重叠和坐标范围。
