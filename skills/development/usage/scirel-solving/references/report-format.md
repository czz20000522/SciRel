# 报告格式

报告写成一篇简短的技术报告。读者先要知道答案，再决定是否看方法和细节。报告语言跟随用户。

这份七节报告是任务的主交付物。宿主平台自带的简报、摘要或交互可视化只是可选的附加产物：用户没要求就不做，做了也不能替代这份报告。不要添加用户没有要求的交付物。

## 结构

二级标题按以下顺序：

| 章节 | 内容 |
| --- | --- |
| 答案 | 几句话回答用户原来的问题，带主要数字，只写会改变结论的限制；流程和检查记录放附录 |
| 问题与理解 | 用户问了什么，我怎样理解，关键口径及其来源（用户确认 / 题目给定 / 未经确认的假设） |
| 物理模型与方法 | 从物理判断到公式到求解思路，见[物理方法](method-design.md) |
| 结果 | 核心指标的小表、图和对图的说明 |
| 讨论 | 决定结果的主导物理机制及其验证，适用范围和没有覆盖的内容 |
| 结论 | 用一小段收尾，说明用户可以怎样使用这个结果 |
| 附录 | 验证结果、完整数值表、复现方法 |

英文报告使用 `Answer`、`Problem and understanding`、`Physical model and method`、`Results`、`Discussion`、`Conclusion`、`Appendix`。

## 写法

- **有效数字：** 正文通常 2 到 3 位，够表达差异即可。原始精度留在数据文件，附录的表最多 4 位。
- **用物理语言说影响：** 比如“端部的场约为中心的一半”。不要只堆数字。
- **不越权：** 用户没有给判据时不判定“可用”或“合格”，但要讲清楚影响，并说明用户可以怎样对照自己的要求。
- **数字可追溯：** 正文数字从保存的结果读回，最好由脚本填入。
- **图：** 每张图有图注。正文说明从图上能看出什么。图只展示物理量和物理问题，不画代码流程或工具使用情况。坐标范围要让关键差异看得见。生成后必须实际打开查看（像素统计不算），检查重叠、图例遮挡和范围。
- **讨论要找主导机制：** 指出决定结果的主导物理机制，用一次只改变一个因素的对照计算验证归因，并说明各因素的大致贡献。避免因果倒置，例如把结果的表现当成它的原因。
- **失败先解决：** 检查失败时先查原因并修正，见[结果检查](result-checks.md)。查清后仍解决不了的失败和未运行的内容必须写明。已查明是检查错误的不算失败，只在附录说明改了什么。
- **确认如实写：** 只有用户在对话中确认过的才写"已确认"；题目给定的写"题目给定"；其余标为假设。
- **大表放附录：** 正文的表控制在 10 行以内。
- **图随报告交付：** 即使平台另有可视化流程，报告本身也要带图。环境里没有 matplotlib 就安装；确实无法安装时，写明原因并按下面的方式声明。
- **提到 SciRel 的方式：** 某一步用到了，就在方法里顺带一句；不列算子清单或映射表。

## 校验

校验器是本 skill 的 [scripts/validate_report.py](../scripts/validate_report.py)：

```sh
python <本 skill 目录>/scripts/validate_report.py <path>/REPORT.md
```

它只用标准库，检查章节顺序、图和图注、方法章节里没有代码块和实现细节、正文有效数字、未解决的失败已写入报告。它不判断物理是否正确，物理内容要靠人读。

确实不需要图或公式时，在报告里声明，校验器会接受：

```markdown
<!-- report: figures=none; reason=这是一个概念问题，答案是一句定性判断 -->
<!-- report: math=none; reason=只比较定义，没有用到公式 -->
```

## 目录约定

```text
<case>/
  request.md        阶段 1：用户原话和已确认口径
  method.md         阶段 2：物理方法
  solve.py          计算和检查
  make_figures.py   画图
  make_report.py    从保存的结果生成报告（数字不手抄）
  data/             原始精度结果和 checks.json
  figures/          报告中的图
  REPORT.md         最终报告
```

文件名不强制，但产物要齐。写法示范见[示例](example-report.md)。

## 复现与交接

附录的复现部分要让别人能重跑并评估结论，通常包括：

- **需求：** 用户原话、口径及来源、仍未知的量；
- **选择：** 实际用过的检索词、选用的 SciRel 能力及其版本标识、选用理由；
- **执行：** 补充计算及其限制、实际运行的命令、保存的输出、检查结果（通过 / 失败 / 未运行）。

结果要交给其他团队或平台继续使用时，可以把这些整理成一个单独的交接文件放在任务目录里；一次性的回答不需要。正文的数字来自保存的输出；如果用了[交付辅助工具](delivery-tool.md)生成的数值陈述，引用时保持原样，额外的物理解释另给依据。
