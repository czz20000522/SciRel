# Check the user's result

Use the selected asset's contract and diagnostics. This is consumer-side scientific checking, not D2 requalification or host audit/recovery implementation.

1. **Right computation:** map the confirmed physical facts to actual arguments. Check units, signs, axes, domains and boundary conditions. Verify any nontrivial connection between assets; successful parameter binding alone is insufficient.
2. **Valid execution:** inspect returned status, convergence and diagnostics. For the requested output choose discriminating checks: residual, conservation, symmetry, a known limit, an independent reference or refinement where applicable. Finiteness alone is not correctness. Do not reproduce the entire algorithm merely to claim independence; separate algebraic/self-consistency checks from independent evidence.
3. **Usable delivery:** For saved numerical tables, use the [executable delivery tool](delivery-tool.md) to read back, render and replay the delivered statements and plots. read the saved file, verify its quantities, units and required coverage, and derive the report's numerical summary from it. Format numbers and threshold decisions from program variables into the report. Inspect final figures; use available fonts or supported labels instead of repeating missing-glyph output. A requested code entrypoint must run on the supplied inputs. Do not substitute a written plan for executed results.
4. **Honest conclusion:** distinguish pass, failure and checks not performed. Scientific failures remain visible; do not weaken tolerances, omit failing points or relabel a weaker model. Answer only what the computation establishes. If a required independent correctness claim cannot be supported, say so.

The harness may record tools, outputs and runtime identity or support continuation. Use those facilities as authorized; their absence does not authorize inventing receipts or adding a SciRel logging/session service. A concise user explanation is enough unless a detailed report is requested.

For a disputed interpretation, separate three questions: what the delivered data show, which checks actually support that observation, and whether an additional physical inference is warranted. Retain the comparison's input scope and failure state in the program's existing results. Do not explain a failed reference comparison away by citing a generic library limitation unless the differing term is active in this run and the explanation has itself been checked. If representations differ, clarify the requested scope instead of silently dropping components or asserting equivalence.
