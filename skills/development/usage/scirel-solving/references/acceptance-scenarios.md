# Behavioral checks for the solving method

These source-local scenarios assess the method, without fixed capability counts or target answers.

| request condition | observable behavior |
| --- | --- |
| a missing step has a defensible public formula | implement and test the supplementary step, then deliver its bounded result |
| a step requires unavailable data or a user-owned physical choice | name the missing fact and give the bounded result still possible |
| a needed capability is absent from the public layer | use only public methods; do not inspect private implementations or acceptance material |
| invalid data, interface mismatch, numerical limit or implementation defect | distinguish the class and preserve the actual failure |
| a fuzzy but answerable multistep request | settle material assumptions, execute applicable calls, check the result and disclose the claim ceiling |

A delivered number must have actual execution evidence. A scientific supplement needs a check and disclosed limits. Method acceptance is separate from correctness of any particular scientific result.
