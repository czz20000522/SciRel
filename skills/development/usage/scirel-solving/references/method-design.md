# 写物理方法

方法章节写给物理专业的读者。读者应该能从问题出发，一步步跟到结果，并判断每一步的物理假设对不对。

## 要写什么

按下面的顺序写，让每一步都从上一步自然得出：

1. **物理判断：** 问题的物理核心是什么，什么效应决定答案。
2. **模型与假设：** 保留什么，忽略什么，为什么可以忽略。
3. **定律与公式：** 用什么定律，得到什么方程或解。关键公式要写出来。
4. **求解思路：** 怎样从公式走到要求的量，解析还是数值，为什么这样选。
5. **怎样确认算得对：** 有哪些极限、解析解、对称性、守恒量或独立方法可以对照。

## 不写什么

数组形状、轴序、函数调用次序、文件名和数据流都不属于方法。这些放在代码和复现说明里。

## 怎样提到工具

某一步恰好用到 SciRel，就顺带注明一句，比如“单环响应这一步可用 `scirel.field` 的现成函数”。用 NumPy、SciPy 或自己写的代码同样正常，不需要标注。不要每步都对应算子，也不要为了展示而改用某个算子。

## 模板

```markdown
# 物理建模与方法设计

## 物理判断
（问题的核心物理，什么决定答案）

## 模型与假设
（保留的物理、忽略的物理和理由）

## 从定律到求解
1. （定律和公式）
2. （如何得到要求的量）

## 如何判断算得对
（可对照的解析解、极限、对称性、守恒量或独立方法）

## 图
（每张图打算回答什么问题）

## 确认状态
（用户是否确认过，确认了什么）
```
