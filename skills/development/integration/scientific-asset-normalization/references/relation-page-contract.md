# Canonical scientific document preparation

Use after comparison, repair and assembly stabilize identities and runnable code.
The sole formal contract is [scirel.asset-document.v1](../../../../../docs/requirements/asset-documentation.md).
Do not create a second normalized relation page with the same facts.

Reuse unchanged exact documents. Absorbed inputs retain target binding, source lineage and comparison evidence.
Partial overlap does not eliminate an independent public contract. Generate only retained new/changed assets and
genuinely changed dependencies; parallelize independent stable families.

Read code, signatures, graph YAML, tests and D1 evidence anchors. Recover explicit facts from these materials.
For units, conventions, assumptions, applicability, failure semantics or provenance that cannot reliably be
recovered, consult the minimum existing scientific record or investigate. Never guess from names or outputs.

Follow the schema for relation/direction, ports/units, assumptions, API, dependencies, examples, failures,
verification limits and public provenance. Graphs include order, state and bounded feedback.
Review prose adds only delta and rationale. Human pages and catalog are projections of the exact document.

Validate via scripts/validate_asset_documents.py with runtime signature and examples against actual source/wheel.
Resolve dependency closure in the same catalog. An incomplete document cannot be exposed as a catalog entry.
Development catalogs are permitted before approval with development status explicit.
Pure prose correction reuses valid numerical evidence; scientific contract corrections revalidate invalidated
claims and dependencies and create a successor when the previous snapshot was frozen.
