# Scientific computation validation

Read the shared operating contract once: [development lifecycle](../references/scirel-development-core.md). During extraction, the [extraction skill](../../extraction/scientific-computation-asset-extraction/SKILL.md) governs instead. Do not reload it for each routed sub-skill.
This is the single validation route for D1 source-fidelity, D2 scientific/numerical correctness and declared D3 functional reassembly claims. It proves named claims for one exact target. It does not choose extraction boundaries, implement repairs,
normalize candidates, approve assets, write stage state or release a package.

## Trigger and required input

Use this skill when a caller names a claim and asks for test design, execution or evidence assessment. Select the mode first: D1 compares a frozen source candidate; D2 evaluates an independent scientific/numerical claim; D3 evaluates a declared terminal functional reassembly claim. Require
exact target/dependency digests, public scientific/port contract and applicability, claims plus exclusions, source
or independent reference identity, authorized runtime/profile and output path. If source/runtime observations are
missing, route to [runtime dataset construction](../scientific-runtime-dataset-construction/SKILL.md); do not infer
an oracle from candidate output.

Choose one claim mode:

- `source_fidelity`: compare source output/state/failure for D1; source defects remain source issues.
- `scientific_correctness`: test an independently stated equation, convention, limit or physical closure.
- `numerical_correctness`: test discretization, conditioning, stability, convergence and declared failures.
- `composition`: test units, axes, state ownership, order, branches, exceptions and reproducibility.
- `functional_reassembly`: test complete terminal output/state for declared source-free cases.

Source parity answers only `source_fidelity`; imports, compile, similarity and test count are not independent
scientific evidence.

## Priority execution card

Select the claim and its risk matrix before writing tests. The default matrix
is normal, lower-bound, upper-bound, degenerate/branch, failure and composition
cases, with only the applicable rows retained and the reason recorded. Attack
units, shapes, state transitions, exceptions, conservation or symmetry,
conditioning, convergence and serialization where they can distinguish a
sample-specific implementation from the claimed relation.

Keep two evidence sources separate: tests shipped with the SciRel capability
protect the public relation; tests generated by an outbound agent protect its
user task and glue. A benchmark oracle may be used after an isolated run, but
the validator must not manufacture an oracle from candidate output and a real
user task does not depend on a hidden answer. Return the matrix, exact
observations, failures, `NOT_RUN` rows and reopen condition as part of the
claim result.

## Bounded workflow

1. Freeze target, inputs, denominator, applicability and tolerances. Keep original grids, threshold neighbors,
   boundaries, failure rows and `atol=0`/other explicit criteria.
2. Build an independent oracle or reference and name its provenance. Separate source-runtime, wheel-runtime,
   development and reference dependencies; a missing tool is a runtime gap, not a numerical pass.
3. For D1/source_fidelity, cover the frozen source denominator and every retained capability required by that claim; for D2, cover the target and affected reverse-dependency closure; for D3, cover every retained capability only when the claim explicitly concerns complete reassembly. In every mode spend deeper cases on algorithmic risk, coupled state/iteration, conditioning and boundary sensitivity, and use a separate holdout only when the selected claim requires it.
4. Execute in the authorized environment, verify runtime identity before import, and keep source-free runs free of
   undeclared source mounts/network. Record command, case counts, observations and exact failures.
5. Interpret only the selected claim. Rerun changed behavior and affected reverse dependencies; do not relax a
   tolerance or silently switch model/asset. Preserve `failed`, `blocked`, `NOT_RUN` and inapplicable rows.

Return exact observations, metric/criterion, evidence hashes, claim ceiling, untested scope and reopen condition.
`pass` applies only to the named gate; it never advances D0-D3, approval or release. If a validator disagrees with
this method, record `tooling_defect` while preserving the scientific result.
