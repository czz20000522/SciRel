# SciRel 架构与科学资产合同

本文定义 SciRel 自身的长期边界。CodeFusion 提供已经完成人工准入的精确输入；SciRel 负责把这些输入维护为一个可安装、可组合、可验证的 Python 科学关系库。CodeFusion 的数据库、Rust owner、审核工作流和源项目目录都不是 SciRel 的运行时依赖。

## 核心对象

### Operator

Operator 是一个具有稳定科学身份和明确合同的最小可调用关系。其身份由关系方向、模型与假设、几何与坐标、边界或闭合、单位、轴序、shape/dtype、适用域、数值方法以及失败行为共同决定；名称、模块路径、源码相似度或少量相同样例都不能单独证明等价。

Operator 的规范运行入口是普通 Python callable。函数签名是公共接口的一部分，结构化输入输出合同补充参数名无法表达的单位、shape、轴序、适用域和失败语义。REST、CLI 或平台工具可以包装 callable，但只是适配层；源码块属于实现与证据，不是调用协议。

### TaskGraph

TaskGraph 是组合能力，也是普通 Python callable。它的规范定义是有向、类型化的数据流图，而不是顺序函数列表：

- 节点引用精确 Operator、嵌套 TaskGraph、调用方端口或合同允许的 glue。
- 边描述端口、数据含义、必要转换、条件和失败传播。
- 普通数据依赖必须无环，并可拓扑排序。
- 循环只允许作为显式反馈合同；每条 feedback edge 以稳定 ID 一一对应一个合同，并声明状态所有者、初始状态、更新顺序、收敛/停止条件、迭代上限和未收敛结果。
- 调度器可以把某次运行投影成顺序步骤；该顺序不是图的科学身份，不能替代节点和边合同。

因此，普通 TaskGraph 是 DAG；Picard 等迭代能力是“无环单步图 + 有界反馈控制”。把迭代按轮次展开后，每次实际执行仍形成有限的有向执行记录。不得用未标注的环、隐藏重试或调用顺序偶然性表达科学反馈。

TaskGraph 定义与运行实例分开：定义绑定公共入口和精确依赖；实例保存本次参数、状态、分支、迭代和结果。任务参数属于实例，不进入可复用资产身份。

### 科学身份、实现与来源

一个科学身份可以有多个来源或工程版本；共享实现也不意味着两个科学身份可以合并。每次整合必须选择并记录下列关系之一：复用同一身份、保留明确变体、新增能力、兼容替换、仅共享内部实现，或因证据不足保持未决。

来源和许可证义务随身份保留。参考项目的行为是证据，不是 SciRel 权威；采用参考行为时保留其成立条件、适用范围和已知反例，并用 SciRel 合同与回归测试确认最终行为。

## 三个边界

### 准入与 provenance

`provenance/admitted-assets.json` 保存 CodeFusion 已准入输入、最终人工决定、精确版本树、内容摘要和依赖绑定。它是冻结的治理输入，不能因 SciRel 重构、措辞调整或重新组包而改写。候选、机器检查通过或 AI 建议不等于人工准入。

### 维护源码与公共 API

`src/scirel/` 是独立演进的库源码。公共 API 按科学领域组织，Operator 和 TaskGraph 都通过普通 Python callable 暴露。内部组合、校验和适配代码不得成为第二套科学事实，也不得在 wrapper 中隐藏新公式、插值、闭合、几何重建或离散规则。

科学行为变化包括公式、单位/轴序、默认值、边界、失败行为、数值方法或 TaskGraph 依赖重绑。此类变化先以失败回归明确差异，并按需要形成新的科学候选和审查；行为不变的工程重构仍要保留旧合同和回归证据。

### 发行与目录投影

`scripts/build_admitted_distribution.py` 从精确准入账本生成 admitted-only staging、wheel、内置 manifest 和内容锁。组装成功只产生待发行候选，不产生批准或发布事实。

面向大规模发现的 catalog 应是从同一发行内容锁重建的投影，而不是新的真值。每条精确记录至少需要：

- 稳定资产 ID、kind、公共 module/symbol 和运行时 signature；
- 结构化输入输出，以及模型、几何、边界、单位、轴序、shape/dtype 和适用域；
- SciRel implementation version 与稳定依赖 asset IDs；
- provenance 摘要、验证范围和证据上限。

不得从函数名或源码猜补缺失的科学元数据。当前准入账本与 wheel manifest 已覆盖入口、准入和依赖绑定，但尚未覆盖上述完整发现合同；在补齐可信元数据前，应把它标记为 metadata gap，而不是生成看似完整的目录。

标准 exact record 使用 `scirel.asset-document.v1`。MCP、Codex、Claude Code、CodeFusion、CLI 和云执行平台只消费同一份 record/catalog/wheel；adapter 负责协议、权限与执行环境，不得成为新的资产身份或科学合同来源。

## 大规模发现

资产规模增长到数万 Operator、数千 TaskGraph 时，不把精确合同一次性放进模型上下文。目录按以下层级提供渐进披露；分片、稳定 ID、反向依赖和增量构建的详细合同见[规模化目录合同](catalog.md)：

```text
领域/关系路由索引
  -> 有界候选摘要
  -> 最终候选的 canonical contract 与 release binding
```

路由优先使用输出、关系方向、模型、几何、边界、生命周期、单位/轴序/shape 和适用域；名称、来源项目、关键词或向量相似度只提高召回率，不能覆盖类型化不兼容。每次检索记录实际加载的 snapshot、范围、候选和未搜索区域；预算耗尽只能得到有边界的 shortlist 或 metadata gap，不能据此声称“没有该能力”。

## 依赖与失败原则

- 科学函数必须在没有 CodeFusion、源项目 checkout、数据库和网络的环境运行。
- TaskGraph 绑定精确依赖闭包；缺失、冲突或未准入依赖 fail closed。
- glue 只做明确且无科学含义的重命名、结构转换、无损单位/dtype/轴序转换或状态传递。
- 每项证据只支持其实际覆盖的模型、输入域、容差和运行环境；测试通过不扩张科学结论。
- 公共 API 的破坏性变化必须说明调用方、版本影响和迁移路径，不能静默删除旧入口。
- 每个资产必须有可机器解析的直接测试归属；TaskGraph 精确依赖和 Python 共享模块 import 形成反向影响图。日常变更从该图选择最小闭包，无法归属时扩大到全套，不能以速度为由跳过不确定影响。
