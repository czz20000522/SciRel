# SciRel 0.1.0.dev9

这是 Git 管理的开发候选说明，不是公开发行批准。

- `pyproject.toml` 是版本的唯一来源；源码 checkout、wheel、catalog 和文档快照都由同一冻结提交生成，历史版本通过 Git 提交、tag 和本目录短说明恢复。
- wheel 仍是纯 Python 的 `py3-none-any`，不把 Octave 等系统运行时伪装成 pip 依赖，也不把未验收的平台写成通过。
- 当前候选的确切 Git 提交、wheel 摘要、文档选择、能力计数、catalog 和平台回执只在仓库根目录的 [`release/CURRENT.json`](../../release/CURRENT.json) 中绑定；该文件随 ref-bound 构建更新，短说明不复制这些动态字段。
- 文档重资格化保留完整能力分母；Linux 专属 fluidBW 文档继续保持 dev8/平台专属边界，不从总分母中静默删除。
- 外部文档快照和 catalog 只作为绑定 Git 提交的生成物保存，不向仓库提交完整版本副本。
- Linux amd64 + CPython 3.14 以及 macOS arm64 + CPython 3.14 已完成固定三 wheel runtime wheelhouse 的离线安装验收；两个平台仍保持 `PARTIAL`，因为完整科学能力闭包尚未建立。
- 文档手册只保留 `tools/docs/handbook.json` 一个 Git 源；260 项发行选择由构建器按选择集动态投影，旧版 handbook 快照从当前树移除并由 Git 历史恢复。

当前候选的确切绑定以仓库根目录的 [`release/CURRENT.json`](../../release/CURRENT.json) 为准。它是协调元数据，不是第二个版本源；旧 dev8 wheel、selection 和回执仍从 Git 历史及旧短说明复核。

当前技术状态仍不是公开发行：Windows、macOS 和未完成的科学/native 闭包保持 `NOT_RUN`、`PARTIAL` 或其他真实状态；平台回执、文档回执和 catalog 摘要不能替代科学专家、再分发或 release approval。
