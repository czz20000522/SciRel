# 科学手册编写与持续维护

SciRel 手册按学科、科学问题和学习顺序组织，帮助读者找到可直接调用的科学关系与复合求解入口。继续使用现有白底黑字、左侧目录树、公式渲染、代码高亮和右上角复制交互。来源项目不作为导航分类；来源、许可与验证依据保留在正式函数参考中。

## 内容分工与唯一科学依据

- `catalog/examples/` 中的 `scirel.asset-document.v1` 是当前已收录能力的唯一正式科学文档。它定义科学关系、输入输出、单位、默认值、适用域、失败行为、公共 Python API、实现版本、依赖与验证限制。该目录是依赖闭合的开发记录集，不是全部公共 API 的完备清单，也不是同一个 wheel 的发行清单。
- `tools/docs/handbook.json` 是 `scirel.handbook.v1` 的学习目录，只保存章、主题、简短导读、精确资产 ID 与可选教程 ID。它不重复保存签名、公式、单位、版本、完整适用条件或科学批准结论。构建时从正式文档取得这些内容，不能把目录导读变成第二份科学合同。
- 教程解释一个具体问题怎样用已有能力解决，并绑定实际运行的案例与结果。现有 `tools/docs/magnetostatics/` 是完整案例的结构示范。仅有主题导读与参考入口的内容应保持这一身份，不制造未运行示例或把预期输出展示成实际结果。
- HTML、HTTP 和 CLI 消费同一构建快照。Agent 可以按手册、主题、摘要、精确文档及依赖逐层读取；任何查询入口都不能另行补写科学字段或改变资格。
- 面向读者的正文默认中文。`tools/docs/zh/` 保存逐项审阅的中文说明并绑定原正式文档字节摘要；保留参数名、单位、数值、原示例代码和资格。原文变化后重新审阅翻译，禁止仅换摘要消除失效。原文内部矛盾显式标注，后继合同修正另记，不静默抹去冻结原件。

阅读正文中的行内公式使用 `$…$`，参数或代码标识使用单反引号；构建器只处理这些显式标记。完整代码始终放在示例代码字段，禁止让排版过程执行代码或改变算式。

正式字段及冻结时机以 [资产文档要求](requirements/asset-documentation.md) 为准。阅读与构建入口见 [可查询科学手册](searchable-documentation.md)。目录覆盖、示例执行、安装包资格、全项目拆解、人审与发行是分别记录的事实。

## 目录与主题

API 参考沿 SciPy 的浏览方式组织：左侧只列科学领域，领域正文按问题设小节，每节用“函数 / 复合入口—用途”表格链接到独立函数页。函数页继续显示同一领域导航；右侧列当前页的小节。指南保留更深的学习目录树。两者共用 `handbook.json` 的归属与摘要绑定的中文说明，不额外维护一份函数清单。

目录采用以下结构：

```json
{
  "schema": "scirel.handbook.v1",
  "title": "SciRel 科学计算手册",
  "introduction": "手册导读",
  "chapters": [
    {
      "id": "electromagnetism",
      "title": "电磁学：磁场与线圈",
      "discipline": ["物理学", "电磁学"],
      "introduction": "本章解决的问题及边界",
      "topics": [
        {
          "id": "coil-vacuum-fields",
          "title": "从单个圆环到线圈组的真空磁场",
          "introduction": "选择入口的学习导读",
          "assets": ["scirel.field.multi-coil-vacuum-field"],
          "tutorial_id": "magnetostatics"
        }
      ]
    }
  ]
}
```

此片段只解释格式，不能作为完整目录直接构建。章和主题 ID 全局唯一，使用以小写字母开头、仅含小写字母、数字和连字符的稳定标识。`discipline` 按通行学科由宽到窄列出，不使用来源库、设备、实现语言或内部阶段名。

每个已收录正式资产恰有一个主要主题。依据其实际求解问题、定义、API 和适用条件选择位置，不能仅按文件名、Python 模块或来源项目自动分类。一个主题可包含关系叶子、变体和复合入口，介绍顺序可从简单调用过渡到完整任务。不要强制“一节一函数”或“一条公式一算子”，也不要为每个参数组合新增复合资产。

其他主题可以通过文字说明相关能力和已有链接引导读者，但不在 `assets` 重复登记同一 ID。章节移动不改变科学身份；科学资产改名、吸收或拆分时，先完成正式文档和依赖的一致性处理，再更新目录。构建遇到缺失资产、重复主归属或正式记录未被目录覆盖时应失败，不能静默隐藏、猜测替代或生成占位科学内容。

已有运行证据的专用教程目前是 `magnetostatics`。新增 `tutorial_id` 前，应同时实现对应渲染与绑定验证；不能仅添加标识就声称完整案例已经可用。没有教程时仍可发布有依据的导读与函数参考，并明确案例尚待补充。

## 写作顺序：问题、调用、结果、解释

每个完整教程按读者解决问题的顺序提供：

1. **问题与目标**：说明想计算什么、已知什么，以及输出怎样回答该问题。
2. **模型与假设**：在代码之前说明决定可用性的几何、坐标、对称性、闭合和边界，链接完整适用条件。不要让读者执行后才发现关键限制。
3. **输入与单位**：给出可复现的实际输入，注明单位、数组形状与轴序、归一化和必要数据。磁通、电流权重、速度标度等容易混淆的约定应在组合处明确。
4. **公共调用**：使用安装包真正存在的 Python 入口。单个算子展示其直接调用；稳定复合任务展示 TaskGraph 的普通调用入口，并按需展开组成关系。教程可以做输入准备与结果展示，不能暗藏未登记的新科学算法。
5. **实际结果**：保留真实运行产生的数值、图表或诊断；标出有效位数、误差量或比较基准。预期结果与实际结果分别记录，图表从冻结结果生成，不手工发明点值。
6. **结果解释**：解释数量级、趋势、对称性、守恒或极限检查，以及这些检查具体支持什么。算例成功不扩展原合同的科学资格。
7. **限制与下一步**：说明该例不能回答的问题、失败或不收敛如何识别，并链接后续主题和精确函数参考。

代码显示与复制应保留原始缩进、空格和换行；长行可横向滚动，输出与可执行代码分别显示。代码语言显式标注，不通过自动猜测改变展示。数学公式保留可供 Agent 和辅助阅读的同义文本；使用当前渲染器真实支持的格式，不能把未解析的 LaTeX 当成已渲染公式。

复合关系要核对单位、坐标、归一化、数据形状、状态与失败传播。普通依赖图为 DAG；反馈和迭代明确初值、顺序、停止条件、最大步数与不收敛结果。节点分别通过验证不代表组合已通过。需要新增便利入口或复合关系时，应先按科学资产流程实现与验证，再写教程调用。

## 运行绑定与可重复结果

遵循现有教程的 `chapter.json`、`example.py`、`results.json`、图表生成脚本及 `execution.json` 分工。页面代码应从已运行脚本的明确小节提取，避免另一份代码逐渐漂移。执行记录绑定源码提交、实际安装 wheel 与必要依赖、示例和数据字节、实现文件、运行命令、退出状态、结果及检查。缺失事实记录缺失，不从终端打印、文件存在或作者成功声明推断闭环。

涉及正式使用能力的案例，应在无原项目 checkout、无 SciRel 源码导入回退的独立安装环境实际运行，只依赖所选 wheel、声明依赖和冻结输入。记录是否断网及必要运行条件。教程不删除审计来源；“不依赖源码”由隔离环境、导入位置和实际执行证明。精确选择性 wheel 的案例只证明其对应范围，不代表当前宽 wheel、整项目或任意平台通过。

科学实现、默认值、单位、失败行为、必要输入或依赖发生变化时，按反向依赖识别受影响案例，实际重跑后重新绑定结果。纯导航或排版变更可以复用字节未变且仍有效的执行证据，不为了生成页面反复运行全部科学案例。构建器发现旧结果与当前绑定不一致时应拒绝发布，不能只改摘要、改期望值或放宽容差通过。

未来引入类似 Jupyter 的运行单元格时，须先明确精确包和依赖版本、运行隔离、单元格顺序与状态、资源和时间上限、输入与输出保存方式。当前只提供阅读与复制，不用无执行能力的按钮假装可以运行。

## 每批合入后的维护

1. 列出本批稳定资产的新增、修改、删除、重命名与依赖影响，保留变更前后的精确 ID。对照当前 Git 基线逐项整合，不覆盖其他贡献者或冻结前驱。
2. 更新受影响实现的 docstring 和唯一正式文档。检查公共签名、默认值、单位、域、失败行为、TaskGraph 依赖与实现一致；不变资产复用现有文档。只有取得相应证据才能改变验证结论。
3. 更新手册的主主题归属、必要导读与中文阅读说明。新能力没有正式文档时先记录文档缺口，不能凭源码名称补造合同。目录中的引用必须精确解析，全部已收录记录必须唯一覆盖；中文说明须覆盖同一精确集合且摘要有效。
4. 对照计划交付的确切包检查公共 API、组件和传递依赖。正式 catalog release 要求其记录版本与该 release 一致；手册快照可收录不同实现版本，须保留每条原版本，不能把它们重标为一个包版本或暗示全部可在同一 wheel 使用。
5. 重跑受科学变更影响的案例，保留原失败与后继修正，更新真实执行绑定、结果和解释。按影响范围验证文档链接、目录、搜索、复制、公式及 HTML/HTTP/CLI 同源结果。
6. 构建到新的不可覆盖目录，验证清单的字节摘要与源提交，再切换供读者使用的快照。保留旧快照及可追溯身份；不能在原目录覆盖结果或以重新复制历史交付冒充新执行。
7. 将本批实现、正式文档、目录和教程的版本关系纳入交付记录。主控独立接收后逐项合入；技术完成、人工认可、许可及公开发行继续分别记录。

常规维护以实际变化为触发点。目录不是项目拆解计数器，主题数量和资产数量不等于完整项目交付。完整拆解仍以实际安装 SciRel 后保有原项目全部有效核心物理能力为准；手册持续说明已经存在且有确切合同的能力，并将后续新能力接入同一学科结构。
