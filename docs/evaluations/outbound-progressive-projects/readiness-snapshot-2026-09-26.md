# Outbound workflow readiness snapshot (through 2026-09-27)

This is a bounded assessment of selected development evaluations, not a
scientific approval, release decision or statistical success rate over all
tasks. The [four-question baseline](results-2026-09-24.md) tested progressive
P1-P4 requests on an unapproved dev5 wheel and partial catalog. Later cases
used pinned, unapproved development wheels and increasingly complete catalogs.

[synthesis-to-residual trial](results-2026-09-27-synthesis-residual-forward.md)
used dev39/126 assets.
Each linked case has its own artifact digest, raw harness trace, independent
check and explicit evidence ceiling. A later review repair is not counted as
first-pass autonomous behavior.

The development library is not a trusted runtime baseline. A separate
integration freeze reported `0.1.0.dev39`, 126/126 catalog coverage and
`pending_unapproved` on 2026-09-26. The new synthesis-to-residual trial
directly exercises this pinned wheel on one synthetic project; earlier dev24
trials do not validate it by inheritance. The latest
integration handoff also reported no qualified new L1 delivery in the
designated raw-material root. Expert science review, license disposition and
public v1 release remain open. These facts limit claims, but they do not
invalidate the reproducible development software-evaluation outputs.

The [pinned dev39 thermal compatibility regression](results-2026-09-26-dev39-thermal-regression.md)
ran one previously reviewed ordinary project entrypoint on the 126/126
unapproved wheel/catalog after an explicit version-and-digest rebind. It
checks current-package compatibility, not new autonomous behavior.

The current defensible statement is: a neutral local harness can produce
useful, rerunnable SciRel-based **development** projects from staged user
requests, and expert/maintainer feedback can repair observed failures.
Autonomous end-to-end reliability for uncertain science, cross-asset port
binding and result ownership is **not** demonstrated. The new uncoached
graph-edge case supplies a contrasting failure and two-review-assisted
repair, not a reliable pass. Further unseen variants remain open. A later
CodeFusion owner report records a same-package, same-skill adapter path after
two model feedback rounds and a separate human README correction; that is a
bounded comparator, not an uncoached reliability pass. Do not add another global
skill prohibition or gate solely because one corrected case passes or fails.
