# 渐进需求与科学项目出库评估：考官手册

状态：待执行的评估设计；不是通过记录、公共科学合同或发布门禁。

本题组服务于当前“出库链路”任务。原有
[中性 harness 算例记录](../scirel-outbound-neutral-harness-cases.md)
保留为明确需求、已有 TaskGraph 复用的基线；这些成功不能代替本题组的项目级证据。

## 评估目标

检验普通用户只表达模糊目标时，Agent 能否帮助用户形成可理解、可修订的需求，使用 SciRel 科学能力和
必要的工程代码交付可运行项目。项目可以包含嵌套 TaskGraph、多资产数据流、大量文件与接口适配、批处理、
部分失败和多轮需求变化。不预设算子与胶水代码的比例，不奖励代码短、提问多或画出的节点多。

CodeFusion 保持中立 harness，本轮不修改、部署或调用其产品能力。使用独立 Claude Code 会话与 SciRel
方法进行试验，优先复用已跑通的独立环境；实际运行于本机或 Spark 必须如实记录，不混用环境证据。

本题组区分三件事：用户意图是否被逐步理解、工程项目是否实际交付、科学结论是否有相应依据。
一个已验证的小函数不能自动完成项目；诚实报告某个科学缺口也不应阻止不依赖它的可交付部分继续推进。

## 考官、用户与求解者的隔离

- 本文件仅供考官准备和评分，不能放入求解 Claude Code 的上下文或获准文件树。仅改文件名不能构成隔离。
  记录实际工作区、允许读取的材料和权限边界；如果无法阻止读取考官材料，应明确标注为非盲测。
- 考官准备并冻结输入、参考检查、用户背景和变化事件。求解者只收到相应 opening 文件的正文，以及普通
  用户在当时会提供的材料。不得附送本题标题、评分标准、预期 asset ID、目标图结构或参考实现。
- 公共环境说明可以告知可用技能、catalog 位置、解释器和可写工作区；不得把本题解法伪装成环境说明。
  可用技能包括科学请求、资产导航、项目实现与科学验证方法；由求解者按需选择，不强制工具调用顺序。
- “出库链路”Agent 主持试验。用户角色最好使用单独上下文，只收到用户背景、可披露材料及变化事件，
  不读取参考解与评分键；无法分开时逐轮记录披露依据，不能偷偷把考官知识写进用户答复。
- 同一题的澄清、交付反馈、需求变化与修复保留在同一个求解会话。不同题使用干净会话和独立工作区，
  不将上一题代码、检查答案或报告自动提供给下一题。
- 开考后考官不替求解者修改代码、数据或依赖。必要的环境干预单独留痕，该段结果注明受人工帮助。
  用户反馈表达可观察现象，例如“第二个文件没有出结果”，不得直接提供正确函数或修复补丁。

## 用户模拟规则

1. 用户有工作背景，但不知道 SciRel 包名、端口、任务图结构和内部算法。用“没有放电，只看线圈产生的场”
   这样的事实回答，不突然变成专家，主动给出算子名和全部科学参数。
2. 每题准备四栏资料：用户确实知道、用户误以为、文件中可查、用户不知道。求解者可以读已提供的文件，
   用户不能替它复述文件中所有字段。不知道时可以说“不清楚，请说明我该怎么判断”。
3. 不完整不等于故意刁难。求解者问到相关信息时给出用户确实知道的内容；明确索要一份相关材料时，可以
   交出整份自然材料，不能把必要字段人为切碎成猜谜。不要要求问中某个固定关键词才披露。
4. 目标可以通过看样例、比较选项和试用逐渐形成。尚未决定的偏好不作为隐藏唯一答案；接受合理可行的
   提议，并记录用户选择及形成时机。用户尚未提出的新增需求不追溯计为此前失败。
5. 变化按行为事件触发，例如看到第一张图、第一次批量运行、尝试导入新文件，而不是固定第几轮提问。
   不规定必须问几轮，也不把“一次问清所有问题”当成通过条件。评价问题是否易懂、必要、能推进当前工作。
6. 不让用户填满所有工程细节。路径、输出布局、普通文件格式、合理图例等可由求解者决定；会改变物理含义
   的模型、边界、单位来源和结论范围要有依据。用户说“你决定”不允许编造关键输入或提升科学结论。
7. 用户希望“快点给结果”时，观察求解者能否先交付有依据的部分，并用普通语言解释仍缺什么。

## 开考准备与证据

每题开考前，由考官在求解者不可见的位置准备普通项目材料和独立验收方法。这里给出的是材料合同，
不是已完成 fixture；未准备并核对的题不得宣称可执行或通过。

- 固定本次实际 wheel、catalog、skill、模型配置和环境；开发期 partial snapshot 仍是开发证据。
- 原始材料应有自然可读的说明、单位和来源；刻意缺失的信息另在用户资料卡记录谁能提供。合成数据标记为
  合成，不能冒充真实装置。数值、科学检查和允差从对应精确合同与独立依据确定，不能根据求解输出倒推。
- 参考检查可以直接调用相同资产核对输入绑定，但那只是接口/组装证据。要声称独立数值或科学检查，还需
  对应解析关系、独立实现、已有参考数据或适用不变量；区分这两类证据。
- 保留用户消息、实际工具调用、问题与方案演变、生成代码、执行失败、修改、结果及检查。无需统一数据库
  或新评测框架。计划图可以用项目文档或 Mermaid 表达，须对应真实执行，不以绘图替代计算。
- 验收从交付的用户入口重新运行，不手工补参数、补导入或修路径。检查输出回读、局部失败说明、旧结果归属
  和重复运行行为。不得执行隐藏参考代码后把该结果替换成求解者产物。
- 案例内形成的普通脚本、配置加载、格式转换、按 ID 关联、循环、错误处理、导出和报告都可以是正常工程
  胶水。它们不能静默更改科学关系；新插值、闭合、外推或模型要被明确识别并走相应有依据的方法。
- 下文候选能力链用于证明题目可解，不是隐藏的唯一答案。允许科学等效且满足已形成需求的方案；未实际
  覆盖某种组合结构时，将该评估维度记为未覆盖，不能只因选择不同资产就否定正确的用户项目。

## P1：从“看一眼磁场”发展成线圈方案比较项目

首轮只发送 [01-coil-project.md](openings/01-coil-project.md) 正文。

### 用户背景与材料

- 用户是一名刚接触计算的实验人员，有轴对称圆形线圈的矩形截面几何表与几组电流设置，想先得到能讨论的
  图，还没有决定比较哪一项。用户知道目前没有等离子体放电，但不会主动说“真空场模型”。
- 几何表用 mm，电流表用 kA，按 coil_id 关联，行序不同。文件明确给单位、线圈方向与电流符号约定；
  用户不知道字段如何映射到库。求解者需要时交出表及其说明，不直接给标准化 Python inputs。
- 用户能在示意图上指出关注区域，不知道应该计算多少网格点。考官选择远离导线奇点、落在合同支持范围的
  几何与区域；在准备阶段用独立依据确认该题有可计算结果。

### 渐进事件

1. 求解者解释能画什么并询问用途后，用户说明“先看空载时中心附近场分布，让我知道几组设置有什么不同”。
   接受合理的首个低成本预览；不要要求用户选择内部求解器。
2. 看到第一份可运行图后，用户说：“这种图可以，我还有另外几组电流，能不能放在一起比较？以后我想换表
   自己跑，不想每次改程序。”交出其余电流表。
3. 批量入口出现后，交出一个行序打乱且故意漏掉一个 coil_id 的新工况。用户按实际结果反馈：错误结果可说
   “这一组结果怎么怪怪的”，正确拒绝时回应缺项提示，再从实验记录补齐该电流；不能由考官直接修输出。
4. 对比可用后，用户指出关心的是某个指定区域而非全图峰值，并要求保留前一版比较供同事核对。

### 考官能力依据与检查

- 当前开发 catalog 中的 multi-coil-vacuum-field 是可行候选，内含线圈离散、Green 关系与电流叠加；
  具体匹配由求解者完成，题面不告知。采用该路径时核对嵌套能力真实执行并处理多个工况；不能只画嵌套
  方框。科学等效的其他方案按实际覆盖的能力评分。
- 独立核对单位换算、coil_id 关联、请求区域、符号和输出轴序。对合同允许的输入检查零电流、反号、线性
  叠加或对称性；这些检查不能替代未提供的等离子体物理。
- 少一个电流不能默认为零；行重排不能改变物理结果。用户补齐后应实际重新计算该工况。
- 交付包括可运行项目、配置/数据入口、对比图与数值、逐工况状态和运行说明。不强制 Web UI。
- 证明的是科学 TaskGraph 的项目级复用、工程适配与需求演化，不自动等于新增跨资产科学关系已验证。

## P2：把杂乱的平衡文件做成能反复使用的批处理工具

首轮只发送 [02-batch-inputs.md](openings/02-batch-inputs.md) 正文。

### 用户背景与材料

- 用户从同事处拿到多份已经计算好的轴对称平衡数据，想为后续三维程序准备输入；用户不知道网格映射、
  重新求解平衡与后续波计算的区别，需要求解者用输出示例解释。
- 准备三组有依据的合成输入：A 的数组按 [r,z]，B 按 [z,r] 且坐标用 cm，C 同样是合法科学状态但缺一项
  轴标签或磁通约定。A/B 的说明足够完成无损适配；C 的原始导出说明暂在同事处，用户起初确实不知道。
- 避免把非方形数组尺寸当作唯一提示：至少一个变体使用方形数组，轴意义仍依赖标签。另准备会实际影响
  材料支撑的非空 PEC 区域及目标网格说明，不把全 false 掩码当作全部边界覆盖。

### 渐进事件

1. 当求解者确认“已有平衡的前处理”后，用户提供已有数据与目标程序的自然格式说明，说明先处理 A 即可。
2. 第一份结果可用后，用户要求“整个目录都做一遍，坏的单独告诉我，好文件别一起停掉”。交出 B/C。
3. 求解者发现 C 的语义不明时，用户说“不知道，能不能先处理其他的，我去问一下？”随后取得原始导出说明
   再交给它。不能让求解者用插值、猜轴、补零或默认磁通约定掩盖缺失。
4. 用户换了目标网格，并表示原来的部分区域其实不需要；要求输出能被现有下游程序读取，且旧结果保留。

### 考官能力依据与检查

- 合适路径可将 grid-support TaskGraph 作为外层批处理/项目图的节点；它内部已有映射和材料分类，
  用户层仍需要输入解析、元数据绑定、逐项错误处理、输出适配和重复运行。
- 用表示不同但科学状态相同的 A/B 核对单位/转置后的结果；这证明表示适配，不证明任意输入都等价。
  对 C 确认是在有真实说明后才计算，不接受仅按形状猜测的侥幸正确。
- 用一个会改变非空 PEC 区域的输入检查掩码真实参与计算；再核对覆盖、PML 排除及适用的数值参考。
- 检查失败输入不会混入成功汇总，补齐后确实重算；更换网格后不存在旧数组和新说明混用。
- 运行下游最小读取器确认输出格式可消费。胶水代码体量和文件数量不作为科学能力贡献或失败的判据。

## P3：从模糊的射频准备需求发展成嵌套、多阶段计算项目

首轮只发送 [03-rf-preparation.md](openings/03-rf-preparation.md) 正文。

### 用户背景与材料

- 用户为射频方向工作准备材料，已有平衡文件、实验设定中的物种/密度/频率和探针位置，但不知道这些
  数据能得到哪些结果。起初只想“先做点能看的结果”，不知介电响应与波传播/吸收预测的区别。
- 材料按需披露：平衡及坐标/场分量说明、物种记录和密度模型、频率列表、探针位置及其坐标系。不能让
  用户回答内部端口或 Stix 参数，求解者应解释可支持的产出与限制。
- 考官准备一个科学上明确、合同可支持的小型合成场景。必须明确所给磁场是否包含所需分量、冷等离子体
  假设是否为本题接受范围、密度如何定义、探针与场网格坐标一致性；缺少这些依据不能硬凑可解题。
- 初次可解 fixture 明确采用无环向场的合成设定，而非把普通托卡马克数据默认为完整场；这一事实应在
  自然的数据说明中可查。物种在指定有效材料区域均匀，记录数密度、电荷、质量和碰撞率的含义及单位。
  不能把现有标量 species 接口当作已经支持任意密度数组。

### 渐进事件

1. 求解者解释选项后，用户选择“先把已有平衡整理到网格，看看给定频率下材料响应，暂时不要求波传播”。
   这个选择要从解释中形成，首轮不主动给出完整任务链。
2. 第一阶段可用后，用户提供物种/频率记录，希望几种设定能比较，并给出一个有用的简明结果预览。
3. 看到网格结果后，用户说：“我实际只关心这几个探针的位置。位置表是厘米，能不能都整理成一个文件？”
   探针表包含内部点、边界点和域外点；不要提前告诉求解者哪行会失败。
4. 用户追问：“那是不是也能告诉我波最终在哪里被吸收？”用户可接受先交付材料响应与探针结果，但需要
   听懂距离吸收结论还缺什么；不能被大量术语或泛泛拒绝搪塞。

### 考官能力依据与检查

- 当前可行候选链为 grid-support TaskGraph -> cold-plasma-tensor -> complex-rectilinear-interpolation。
  首节点本身已有子算子，后续是新的跨能力数据流，外层还有频率/工况组织。必须核对实际运行中输出确实
  进入后继输入，不能用一个现成 TaskGraph 调用加装饰图宣称动态组合完成。
- 映射出的三分量场不自动等于任意装置的完整磁场；当前映射合同不凭空补出环向场。若用户目标依赖缺失
  分量，需补充有依据的数据或限制本题模型，不能把缺项静默设零。
- 冷等离子体资产有自身密度、频率、共振和数值适用条件。材料 mask 不会自动授权构造密度分布，密度与
  支撑区的关系需有本题依据。使用同一已声明坐标基，不能隐式旋转张量。
- 分开处理平衡覆盖、请求材料、PEC/PML 与数值有效性。未计算区域可以用明确标记的非有限占位表示，
  不能默认为真空；只有有依据的真空区域才可使用相应模型。要包含几何域内但插值邻点涉及未计算区域的
  探针，检验是否能准确解释不可用结果。
- 插值资产允许尾部张量轴，但几何 valid_mask 不保证数值有限；检查实际复数张量、有限性、源域和域外
  掩码，禁止给域外探针偷偷外推。若测试源中含非有限值，需单列几何有效与数值无效。
- 参考应包括节点上的直接结果、具有独立依据的简单介质/对称或极限场景，以及可精确验证的插值输入。
  探针采样结果不等于该位置重新计算的张量；明确本题交付的是哪一种，不能混用两者作参考。
- 波传播、电场或功率沉积若缺少适用资产和必要输入，保留为后续未完成节点；可完成部分仍要交付。

## P4：把“看起来能接”的能力变成诚实的部分项目

首轮只发送 [04-capability-boundary.md](openings/04-capability-boundary.md) 正文。

### 用户背景与材料

- 用户手头只有线圈几何和电流，以为“这些都有了，就能算出等离子体长什么样，再看看加热效果”。
  用户不了解真空场、平衡、介电响应和功率吸收之间的输入差异。
- 没有偷偷藏好一份完整平衡或密度供求解者猜中问题后领取；本题真实存在缺失能力和缺失实验资料。
  用户能提供线圈材料，并允许先做有帮助的、明确标注范围的初步结果。

### 渐进事件

1. 求解者询问物理背景时，用户说“我只有这些线圈文件，其他还没准备，你告诉我先能做到哪一步”。
2. 在方法选择时用户催促：“名字不是都有 field、equilibrium 吗，先接起来跑一下不行吗？”观察是否能用
   非专家可理解的解释指出缺的物理关系，并继续完成获同意的真空场预览。
3. 初步结果出来后，用户希望留一个可扩展项目，写明下一步需要向同事要哪些数据，而不是只得到一段拒绝。

### 考官能力依据与检查

- dev5 真空场图曾把 psi_vac 标为 Wb；dev12 开发快照已把它澄清为约化磁通 Wb/rad，数值未改。
  grid-support 所需磁通也标为 Wb/rad，但两者是否同一参考边界、闭合和物理输入仍须核查。
  真空场轴序为 [N_Z,N_R]、map 为 [N_r,N_z]；有明确轴意义时转置是表示适配，
  不能仅凭名称或单位文字猜测除以 2π 就物理等价。
- 真空场不自动构成含等离子体的平衡，材料边界/闭合也不能从它自动推断。缺少领域依据时，必须给出
  有边界的缺口；partial catalog 下不能升级为整个 SciRel 永远没有相应能力。
- 通过条件是正确分解当前能做与不能做的工作、交付获同意的可运行子项目、提供用户听得懂的补充材料
  清单，并明确未完成目标。既不要求伪造最终加热结果，也不接受只说“能力不足”后放弃全部工作。
- 若用户后来明确选择新科学关系开发，应作为单独的研究实现任务及其验证边界记录；不得计为现有资产
  出库能力通过，也不得自动进入公共 catalog。

## 评分与后续改进

逐题记录结果，不合成一个笼统的“出库全部通过”结论：

| 维度 | 观察 |
| --- | --- |
| 引导与需求形成 | 能否用普通语言给选项、解释后果、识别关键分歧；避免长字段问卷、重复询问已给信息和隐藏假设 |
| 项目交付 | 实际入口、数据适配、批处理、导出和说明能否使用；是否需要考官补代码才能完成 |
| 动态与嵌套组合 | 子图与跨资产连接是否真实执行；新需求是否引起实际计划/代码变化而非仅修改叙述 |
| 科学与数据正确性 | 本次独立依据、实际边界检查、失败传播、证据上限和未知项是否准确 |
| 演进与修复 | 用户反馈是否落实到代码/计算；旧结果是否保持归属；是否通过篡改输入或放宽检查制造成功 |
| 用户负担与效率 | 有效澄清、重复提问、用户无法回答的术语问题、人工救援、时间与成本；不设通用次数阈值 |

区分：按已形成需求完成、完成有用部分但仍有科学缺口、环境阻塞、方法/交付失败。P4 不以不可实现的
最初愿望被全部满足为通过要求；P3 的后续吸收请求也不追溯否定已交付的材料响应部分。

先按当前 skill 跑基线，再针对实际失败改善已有方法。特别检查 project-implementation 中“ask once”
是否被误用为整个长期项目只能澄清一次；已经充分明确的一步可直接做，新的实质分歧仍需重新引导。
将工程适配与科学关系区分清楚，不能把“禁止隐藏新物理”误读成“禁止编写大量工程代码”。

修改 skill 后先复跑原案例作为回归，再由独立考官准备未见变体：改变文件组织/语义缺口所在阶段、
需求演化顺序或下游接口，而不只是换几个数值。变体内容与答案仍对求解者和调试过程隔离。已用于
调试的案例不能再报告为未见任务上的泛化证据。每次只沉淀有成立条件的可迁移方法，不写入案例答案。

题包本身只完成了评估设计。真实执行、fixture 准备、独立检查与最终结果由“出库链路”任务继续记录。
