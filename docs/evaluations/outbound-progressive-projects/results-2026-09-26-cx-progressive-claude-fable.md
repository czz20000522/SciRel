# Claude Code progressive CX comparison

This development evaluation used a fresh Claude Code 2.1.281 session, the complete 74/74 SciRel `0.1.0.dev24` catalog and its matching wheel. The wheel is pending scientific review; KN1DPy's earlier formal qualification was withdrawn. The [manifest](manifests/2026-09-26-cx-progressive-claude-fable.json) binds four delivered snapshots, raw traces, reviewer feedback and independent replay evidence. The CLI selected `claude-fable-5`, while assistant messages reported `GLM-5.3-Flash`; the underlying model identity is not confirmed.

First, Claude received only `conditions.csv`: three complete H/H+ charge-exchange conditions and one missing ion temperature. It produced a runnable fitted-rate project, converted keV to eV and cm^-3 to m^-3, and held the incomplete row without inventing temperature. Only after that first result was frozen did a colleague's velocity mesh arrive with a request to compare the fit against an explicit Maxwellian average of the default Janev cross section while retaining the old deliverable.

The **autonomous second-turn project ran numerically** and preserved the first files. The fit and mesh rates were approximately `(6.097381, 6.058077)e-14`, `(9.982271, 9.920635)e-14` and `(1.194546, 1.187689)e-13` m^3/s. But it manually reconstructed cylindrical volumes despite a matching SciRel quadrature asset in the bound catalog, promoted one 4x-refinement difference into an error claim, and called high-energy clipped samples negligible from their cell count alone. This is an autonomous executable result, **not** an autonomous science-bounded delivery. The [pre-feedback finding](../../../build/verification/cx-progressive-claude-evaluation/independent-stage2-finding.txt) records the exact failures.

After the first separate examiner message, Claude reopened the catalog and composed `scirel.kinetic.cylindrical-velocity-quadrature` into the Maxwellian average. Independent source-free replay intercepted 12 actual quadrature calls, six averages, three fitted-rate calls and nine cross-section calls, with the same three rates, a missing-input row, unchanged old files and byte-stable reruns. It also found one remaining explanation error: the report treated the 0.1955% **computed** contribution of endpoint-clamped cells as if it bounded the unknown true-rate error or explained a share of the roughly 0.6% fit/mesh difference. A second narrow reviewer message produced the final snapshot; only the comparison README changed from the preceding snapshot. It now distinguishes observed refinement sensitivity and computed clipped contribution from error bounds and causal attribution. The [final independent check](../../../build/verification/cx-progressive-claude-evaluation/independent-stage4-check.txt) records replay and exact hashes.

The outcome is a **two-review-assisted, evidence-bounded runnable project**. The final CSV has three computed rows and one `needs_scientific_input` row, while the original runner, README, CSV and inputs remain available. Neither internal agreement nor passing contract calls validates the underlying atomic physics. The experiment reused host scientific dependencies, lacked OS-enforced blind examiner/solver isolation, and does not establish generalization to another problem. The one-line method revision made after this case asks future runs to search the bound catalog again when a newly selected consumer needs a scientific input the user did not supply; that revision was **not** present in this Claude run and still needs a fresh forward test.
