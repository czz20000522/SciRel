# Local adapter-method forward slice for CodeFusion handoff

CodeFusion's Spark four-turn Balmer user project was a bounded shell delivery,
not an adapter-method pass: its owner snapshot selected SciRel skills, but
the reported tool record did not show a `scirel-solving` body read or the
`catalog.discover -> asset.read(detail=document) -> callable.invoke` sequence.
SciRel did not change CodeFusion. This follow-up tested whether the missing
method can be expressed and executed by a neutral harness using SciRel-owned
assets. The [manifest](manifests/2026-09-27-adapter-method.json) pins the
request, wheel/catalog, method files, raw traces, first archive, feedback and
reviewed archive.

The SciRel solving skill now says, **only when an adapter-mediated run is
explicitly selected**, that a direct catalog-file scan plus `scirel` import
does not satisfy that route. It asks the model to leave bounded receipts from
actual adapter responses. `scientific-project-implementation` now directs
the model to read the owner-resolved solving skill body; selecting its name in
a host snapshot is insufficient. A bundled
[thin-adapter reference](../../../skills/usage/scirel-solving/references/thin-adapter-run.md)
keeps the core envelope available when SciRel repository docs are not mounted
inside a user project. These are conditional routing instructions, not a
SciRel-specific CodeFusion kernel rule or a hard-coded scientific workflow.

A local source-free Python probe first constructed the installed
`scirel_adapter.ThinMcpAdapter` against the dev39 development catalog. It
successfully discovered the Balmer emission TaskGraph, read its exact document
with `detail=document`, invoked its documented ports, and reproduced the
known K1 Balmer rate. This proves the SDK-free Python core is callable under
the pinned installed wheel; it says nothing about the CodeFusion product
path. The formal trial then started a fresh Claude Code `2.1.281` session in
a blank project with a synthetic three-row profile, historical JH payload,
unapproved `0.1.0.dev39` wheel (SHA-256 `be5a2a2b...1eef9b8`), complete
126/126 development catalog (root `434249fe...86e3fca`), and the selected
adapter-method host declaration. The CLI label was `claude-fable-5`, assistant
messages said `GLM-5.3-Flash`, and the underlying model was not independently
confirmed. No call or token budget was imposed.

The first raw trace shows actual reads of `scirel-solving/SKILL.md`
(`bf1eb354...8dd22f3`) and its bundled adapter reference
(`72c0059d...cfaa8c3`), then adapter `catalog.discover`,
`asset.read(detail=document)` and `callable.invoke` calls. The generated
ordinary project entrypoint repeats that path and saves operation-derived
catalog root, asset IDs, implementation version and checks in
`output/run_evidence.json`. It computed the same three Balmer/Lyman photon-rate
pairs as direct dev39 calls. A separate extraction outside the SciRel checkout
with the pinned wheel/catalog passed its 12 tests. This is a real local
method-path observation, not just a self-described sequence in the final
answer. Direct calls in the project were used as downstream comparison checks,
not in place of adapter invocation; they are not an external physics oracle.

The first delivery was **not** a reliable reusable project. Independent
negative probes found: an empty K2 temperature made the whole command exit 1
before writing a partial CSV; a new CSV path still overwrote the fixed
`run_evidence.json` for the old result; a changed profile targeting the old
CSV path exited 0 and overwrote that CSV; and the reported no-clipping check
compared rows whose electron and neutral densities also differed, so it did
not isolate temperature. One symptom-level reviewer message followed the
frozen first archive. The project-local repair retained the first CSV and
evidence bytes in an explicit history directory, paired evidence with each
new CSV, reported K2 as unavailable while keeping K1/K3, refused a changed-
input write to an old result path, and used an equal-density/neutral-density
temperature probe instead of cross-row variation. This is **one-review-
assisted**, not an autonomous first-pass pass.

The [reviewed project](../../../build/verification/adapter-slice-20260927-reviewed.tgz)
has SHA-256 `cccc3397d785eb0e0cf31dc288cf81253c8d2636f202d51daecdbbd46e974a7b`.
Independent extraction with the pinned host assets passed 20 tests. Its
ordinary empty-Te command exited 0, produced K1/K3 values and a reasoned K2
row, and replayed the saved case CSV byte-for-byte. A changed-input attempt
on the old case path exited 1 with both old CSV and paired evidence hashes
unchanged. A distinct output path succeeded without changing that pair.
The archived original first-delivery CSV and evidence retained their original
SHA-256 values `d059c010...2e7905fb5` and `0778a55b...951b60`.

Remaining limits matter for the next freeze. The saved coefficient table's
strict D1 qualification is withdrawn and it lacks an external atomic-physics
oracle; the wheel/catalog are unapproved development inputs, not trusted or
public v1. The new temperature probe establishes response at one controlled
in-domain pair, not physical model validity or absence of clipping across all
possible profile rows. Same-input ordinary reruns may replace a result after
only input-file digest comparison; the guard does not pin glue-code identity,
and multi-file CSV/evidence writes are not transactional. The evaluator and
solver shared a host filesystem, host scientific dependencies were reused,
and Claude's tool trace includes Bash commands despite the project's `pwsh`
guidance. This trial does **not** close CodeFusion's own adapter integration.

For the next CodeFusion freeze, keep the same neutral ordinary chat/project
entrypoint, pin the exact wheel/catalog and deployed SciRel skill revisions,
and require one accepted request's typed shell timeline to show the
owner-resolved `scirel-solving` body actually read and actual adapter
discovery, exact-document read and invoke responses with matching catalog
root and asset IDs. The project artifact should retain bounded operation
receipts and numerical/row-level checks, with older user results accessible.
If a direct library program still produces useful files but the adapter
sequence is absent, record that as bounded shell delivery, not same-method
acceptance. CodeFusion remains the owner of its tool timeline, skill
resolution and user-project delivery; SciRel owns this method and adapter
contract.
