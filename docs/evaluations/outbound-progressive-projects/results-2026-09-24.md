## 暴露的问题与修复

1. P1 首版 ROI 在浮点边界漏掉 `Z=+100 mm` 网格层。Claude 在用户要求重点区域后发现并修复，保留旧比较；修复后的区域上下层数对称。
2. P2 目录扫描与 `--check-only` 曾误处理配置/输出；同一会话修正。C 的缺失轴序是有物理影响的元数据，未根据方形数组猜测；获得导出日志后才计算。
3. P4 首版把每线圈总电流施于每根离散丝，使场值高四倍；又将公开 `psi_vac: Wb` 擅自重标为 `Wb/rad`。经两轮反馈修正数值、测试、图和文字；单位约定疑点保留为开放问题。
4. P3 首次张量图把低于离子回旋频率的整段误标为“不适用”，并把 `Re(S)=0` 直接称为“共振”；反馈后撤回。随后又误称线性内插不能过零、把有碰撞写成实际吸收区，均在原会话修正。测试绿并不能替代科学解释审查。
5. P3 初次探针交付仅给最近节点值：内部探针 `(0.28,0.28,0.04) m` 的值实际取自相距约 `0.0583 m` 的节点，且漏检 catalog 中的复值插值资产。用户指出坐标差后，Claude 重新检索、实际调用该资产并形成新的位置采样文件；旧最近节点文件保留作差异证据。
6. P3 首次吸收答复正确识别能力缺口，却过度推断均匀密度/近均匀静磁场意味着“不存在空间吸收结构”，并引入未验证的频率比较。反馈后撤回：未计算波场不等于物理上没有吸收位置。

## 结论与后续

这轮证明中性 Claude Code harness 能在当前开发 wheel 和部分 catalog 上交付逐步扩展的项目，并在用户反馈后完成真实的跨资产动态组合；它**没有**证明无人审阅的一次出库即可可靠，也没有证明 SciRel 的全部 62 个资产、物理适用性或 CodeFusion 产品体验。尤其是 P3 的“首次检索只找到两段链、需求演化时没有重新搜索”和 P4 的“数值归一化/单位标签越权”，应作为方法与科学合同审查的具体样本，而非凭一个案例增加全局阻断规则。

下一步可先在现有 `scirel-solving` / 资产导航方法中局部澄清“新科学输出需求出现时重新检索”和“数值观察与物理解释分层”；对 P4 的 `psi_vac` 约定单独做科学裁决。改动方法后复跑原题，再用未见的文件组织或需求顺序变体验证，不能把本次调试后的成功称为未见任务泛化。
