## 首次结果、救援与修复

1. 首轮能解释“局部冷材料响应”和“波传播/吸收”不同，并提前发现 catalog 中的位置插值候选；但初答曾把 partial catalog 的已检索缺口称为 release 能力缺口。第二轮生成网格 TaskGraph -> 冷张量项目；从用户入口独立重跑退出码 0，8 项结果检查通过。首次参考公式误用碰撞约定，模型自行修正；这不证明装置物理正确。
2. 追加厘米探针时，模型虽重新检索，却没有使用现成插值资产，而是在探针处重新映射磁场和计算张量，并自行把仅在有效**网格点**声明的密度及 PML/PEC 索引掩码延拓到离网格位置。它给 `interior` 和 `pec_neighbor` 数值，9/9 自检仍绿。这是科学前提越界，**首次探针交付失败**。
3. 维护者指出该输入范围后，模型撤回全部离网格值，出现“4 个探针全部不可算”的过度拒绝。从用户语言进一步澄清“只用已经算好的网格结果作位置估计”后，它做出内部点值、其余点留空，但使用项目自写三线性关系；这是已辅导后的项目实现，不是 SciRel 插值资产复用。
4. 维护者再次指出 exact catalog 中 `scirel.geometry.complex-rectilinear-interpolation` 的适用合同后，模型把项目第三节点改为真实调用该资产。它将支撑节点的七个已计算量放回 `[x,y,z,7]` 复值网格，未计算节点保持非有限；对每个频率调用一次，分别读取几何 `valid_mask` 与数值有限性。未在探针处再算密度或张量。最终项目为 `rf-response/`；`CORRECTION.md` 记录撤回及再修复，但 v1 和 v3 的完整 CSV 曾被覆盖，只有部分数值和文字留下。这是证据留存缺口。

### 结论与限制

这次未见结构变体比前一轮 P3 更接近目标出库工作流：用户可以先给基础目标，后续再追加频率、物种和 dashboard 需求；模型会重新规范化新增输出、重新检索资产、使用已计算中间结果和嵌套资产组合，并把物理解释边界写清楚。特别是前一轮失败的“探针处重新计算/越界延拓”没有复现。

仍然不能扩大解释为稳定泛化能力：

- 实际成功 harness 是 Codex CLI，不是 Claude Code；本变体的 Claude 启动配置失败，其他工作区的 Claude 运行已证明它并非整体不通。
- 不是严格盲测，后续输入文件名从首轮可见。
- wheel 与 catalog 均为开发期 partial 版本，不能称为可信 v1 或发布资产。
- 数据是合成切片；结果只证明 SciRel 资产调用、胶水代码、插值采样和失败分类，不证明真实装置物理充分性。
- Codex round2 曾因只读恢复未落盘，需要一次写权限重跑；这是 harness/权限体验问题，应在后续与通用 harness 对照时单独记录。
