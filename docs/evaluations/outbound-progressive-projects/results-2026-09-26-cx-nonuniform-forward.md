# Claude Code nonuniform-mesh forward test

This is a new progressive development evaluation of the one-line `scirel-solving` method change made after the earlier CX comparison. A fresh Claude Code 2.1.281 session received a row-oriented TSV with three complete H/H+ conditions and one missing temperature, then only after its first runnable delivery received a nonuniform velocity mesh without cell volumes. The bound SciRel wheel was `0.1.0.dev24` (SHA-256 `a0c665a7...56c95a0`), with a complete 74/74 catalog root `sha256:030f8a37...974b90`. The method digest was `a03e1155...288641`. These are unapproved development assets; the CLI model label `claude-fable-5` conflicts with assistant message tag `GLM-5.3-Flash`.

The first autonomous project used the fitted CX rate relation, converted the density and energy units, calculated three per-neutral frequencies, and held the fourth row without guessing its proton temperature. The second autonomous turn **reopened the catalog and found the missing producer**: `scirel.kinetic.cylindrical-velocity-quadrature` supplied `cylindrical_volume` to the Maxwellian rate average, with the H/H+ cross section as its callable input. This is positive forward evidence for producer-consumer discovery on a structurally different nonuniform mesh. The old CSV and report were retained, and ordinary entrypoints plus 12 project tests passed outside the source checkout.

The autonomous science explanation nevertheless failed. Its dense diagnostic changed the supplied quadrature's outer faces, yet the report called the difference a quadrature-error bound and attributed part of the fit/mesh offset to it. Its 39.6% hot-case clipped *volume* fraction was not a rate contribution; an independent discrete-sum decomposition found about 3.16% of the *computed* rate in those cells, which still does not bound unknown true-rate error. The Janev/Freeman comparison was also used to allocate the fitted-versus-mesh offset without matched controls. The [first finding](../../../build/verification/cx-nonuniform-claude-forward/independent-stage2-finding.txt) was frozen before any reviewer feedback.

After a reviewer message Claude matched the dense grid's actual faces, calculated both clipped fractions and withdrew error bounds and causal allocation. An independent check then found one remaining report typo: it wrote the asymmetric axial domain as `[-6.85, 6.85]` rather than `[-6.5, 6.85]`. A second narrow reviewer message corrected only that generated text. The final archive and four raw traces are bound in the [manifest](manifests/2026-09-26-cx-nonuniform-forward-claude-fable.json); the [final independent check](../../../build/verification/cx-nonuniform-claude-forward/independent-stage4-check.txt) records actual asset calls, 12 passing project tests, byte-stable reruns and known examiner-command mistakes.

Outcome: **autonomous producer discovery and numerical composition, two-review-assisted scientific explanation**. The method revision has narrower positive evidence than full autonomous project success. Neither the dev24 wheel nor its KN1DPy lineage is expert-approved, no external atomic-physics oracle was bound, dependencies were reused from the examiner host, and examiner/solver file visibility was not OS-isolated. This case does not prove stable generalization or physical correctness.
