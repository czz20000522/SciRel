# 面向用户与 Agent 的科学使用文档

SciRel 长期维护按物理领域组织的使用指南。用户先查找物理问题、量和计算功能，再选择实现它的函数或组合流程。
函数、Operator 与 TaskGraph 是实现层，不作为用户指南的一级分类。一项物理功能可以由多个实现完成，一个实现也可以服务多个物理任务。

## 信息层次

1. **物理领域**：研究对象、坐标和常用量，例如磁约束聚变。
2. **物理功能**：能够回答什么问题，需要什么输入，采用何种模型，结果怎样解释，哪些情形不适用。
3. **调用参考**：实现该功能的公共 Python 入口、签名、单位、形状、默认值、异常和最小例子。
4. **可选依据**：对应的唯一资产合同、来源、验证范围及版本绑定。

科学说明先于调用语法。每个功能页包含问题、物理量、关系或近似、实际功能范围、调用入口、例子与可观察结果、限制和相关功能。
具体端口、默认值和失败合同引用或投影已绑定的 exact document；兼容入口缺少详细科学合同的部分明确标为尚未完成，不从名字推断单位或科学有效性。
测试成功、来源保真、模型正确性和实验校准分别表述。公开入口数量不是合格科学能力数量。

## 单一维护源与多种输出

- `docs/user-guide/` 的 Markdown 维护领域解释、教程和版本说明；稳定 `topic_id` 标识物理功能，不使用函数名作为主题身份。
- 资产的科学合同仍以唯一 `scirel.asset-document.v1` 为准。调用参考与 Agent 记录从绑定合同和实际 wheel 接口投影，禁止再维护一份不同的端口真值。
- HTML 是阅读和网站托管输出；Markdown 是便于审阅、检索和分段读取的源文档。
- Agent 使用小型 `route.json` 定位物理主题，再读取所需主题、API 或合同记录。文件按主题/API 分片，不要求执行 Python import 或在每轮上下文装入整个目录。

同一导出同时绑定科学包版本、源码提交、wheel 摘要、科学合同来源和指南内容摘要。网页、Markdown、Agent 文件保持同一版本。
CodeFusion 或其他网站托管此输出，不能另写一套 SciRel 科学含义。平台的执行状态、任务标识和私有路径不进入用户科学文档。

## 维护与交付

新增或改变对外科学功能时，在 D2 比较去重并稳定合同后同步相应领域页、函数参考、例子及发现入口。
已有物理主题优先扩展；新增实现不自动产生新的物理领域或主题。兼容变体在同一功能中说明差异和选择条件。
文档样例对绑定的实际安装包验证；有效旧例子与数值可按未变运行字节和依赖复用，新增或改变的例子记录实际验证。
原容差、异常与状态约定不因文档叙述改变。源实现未提供的能力不能写入功能列表。

每次向用户或平台交付新包，提供与该 wheel 一致的 HTML 指南及 Agent 发现文件，列出本版范围与未定项。
普通开发文档保留开发身份；生成网页不产生科学批准、发布授权或网站部署。历史 wheel、文档输出与摘要保持只读。

当前实现和构建入口见 [使用指南](../user-guide/README.md)。
