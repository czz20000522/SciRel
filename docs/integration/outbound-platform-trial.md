# 第一次平台接入与环境适配测试

本层验证接收平台能否从现有条件出发，让 Agent 使用确切版本的 SciRel 完成一条真实任务链。
测试包是平台端到端接入材料；本层通过表示该平台在实际记录的环境中完成了所列场景。
它不代表 SciRel 全库功能测试、完整来源项目交付、独立科学正确性或批准发行。

## 第一层的范围

既有径向网格与温度剖面功能链足以覆盖本次安装、调用、附件处理和结果交付。
保留 Q1–Q6：明确请求、文件输入、规定异常、必要澄清、当前检索范围的能力缺口，以及追加需求与结果接续。
Q5 准确报告合同缺口可以通过；Q3 正确保留异常可以通过。

本层不要求补跑所有 exact record、增加其他科学领域、完整 TaskGraph、时间演化或全库回归。
这些是后续科学功能测试的独立范围。catalog 的 partial 声明保持真实，入口数量不代表测试覆盖率。

## 环境要求与平台责任

交付方说明运行条件；接收方检查其实际平台并准备兼容的执行环境。不得假设宿主已有 Python、pip、依赖、容器或 GPU。
平台可以安装解释器，建立隔离环境，或调度兼容的容器、虚拟机或远程 worker。
选择的执行环境必须纳入真实平台任务链，具有明确的文件、执行和结果回传通道。

| 要求 | 接收平台应实现的能力 |
| --- | --- |
| 科学运行环境 | 安装并运行确切 SciRel wheel，满足 wheel 的 `Requires-Python` 与所选功能的依赖条件 |
| 依赖准备 | 获取、安装和校验所选功能的依赖，记录实际版本、来源与安装结果；不能把依赖预装视为默认前提 |
| 数值设置 | 满足资产合同和原容差要求；本次 JAX 剖面任务启用 64 位计算，不要求 GPU |
| 文件与上下文 | Agent 可读取 wheel、同版 catalog、领域文档、出库 skills 及指定输入；平台可逐回合交付用户请求与答复 |
| 可控执行 | Agent 能生成并实际执行调用程序，获得终态、stdout/stderr 和规定异常；保留版本与输入身份 |
| 结果交付 | 保存可读取的 CSV/JSON/PNG，向用户呈现表格、图片并提供下载；追加任务保留旧结果 |

不把 Ubuntu、Linux、Windows、macOS、CPU 架构或某个预装 Python 版本指定为平台宿主的验收前提。
已有参考计算的 OS、架构、Python 和依赖版本只描述其证据适用条件，不能据此推断其他组合已支持。
wheel 的通用平台标签也不保证其原生数值依赖适用于任意环境；接收方须实际完成兼容性适配和执行。

科学运行依赖与测试工具分开：前者按 exact wheel 和所选资产合同准备；图片输出可使用平台已有绘图工具，
或自行安装适用的绘图库。若选用 Matplotlib，它属于本次结果输出工具，不能把它误写为所有科学函数的必需依赖。
安装命令中的 `python` 指已选执行环境的解释器；平台尚无解释器时，应先准备该运行条件。

若遇到不兼容，记录实际失败边界并通过受控环境或执行设施适配。
不得通过替换科学 wheel、改写科学实现、放宽原容差、忽略依赖约束或复制参考答案取得通过。
确切依赖在当前可用环境无法满足时，报告该限制，不猜测其他平台必然可运行。

## Agent 材料与考官材料

| 面向 Agent | 仅面向测试负责者 |
| --- | --- |
| 指定 wheel、运行依赖声明、同版 catalog、领域指南、出库 skills、指定输入与当前回合用户请求 | `expected/`、`expected-results.md`、`agent-expected-behavior.md`、参考比较、后续脚本答复与验收记录 |

原包同时包含两类文件时，平台须先按上述边界分配访问权限，不能把整包作为 Agent 可读目录。
Q4 的澄清答复在 Agent 提问后由测试负责者作为真实用户回合送入；Q6 的追加请求按场景送入，
不能把整份测试脚本连同答复预先加载给 Agent。公开使用文档中的正常教学例子可以阅读，仍须证明本次实际调用。
隐藏追加输入可作为后续防抄答案检查，第一层不因此扩张为完整科学功能测试。

## 最小验收记录

记录实际平台版本与入口、模型身份（可取得时）、执行 OS/架构/解释器与依赖版本，
解释器和依赖如何准备、wheel/catalog SHA-256、实际读取的合同与 skill、所选调用、输入摘要、
执行终态及输出文件摘要。Q1–Q6 分别记为通过、失败或未测试；标明失败在环境准备、执行、任务行为还是交付阶段。
不要求平台采用 SciRel 开发侧的 session/job/schema/工具名；公开科学合同不加入私有平台字段。

上传、静态审查、顶层 import 或离线 Python 成功只证明相应步骤。
第一层通过需真实的平台需求→澄清/检索→环境准备→安装包调用→结果呈现/下载及接续证据。
运行失败是本层有价值的观测；平台应补齐阻塞的产品能力并复测受影响场景。
若缺陷位于 SciRel 的材料或合同，单独报告并交由相应维护者处理。

## 材料职责与出库方法

wheel 与依赖声明提供实际运行实现；同版 catalog 提供渐进发现与 exact 科学合同；
物理领域指南说明功能、输入、调用和含义；skills 指导理解需求、澄清、匹配、执行与结果解释。
skills、指南、考官数据和平台适配不进入科学 wheel。

- `scirel-solving`：规范化用户需求、必要澄清、制定计划与解释结果。
- `scientific-asset-navigation`：渐进检索、合同匹配和部分检索范围的缺口处置。
- `scientific-project-implementation`：准备并执行本次任务入口，保存、读取和接续结果。

按任务需要加载；提供方不交付替代求解器，也不要求先搭建一套 SciRel 专用平台。

## 长期维护

同一测试版本绑定 wheel、catalog、指南和 skill 摘要；保留旧材料与失败证据，新说明和材料另记身份。
修复断链、分离考官数据、完善回执、校验摘要与许可说明属于材料质量维护，不能被理解为扩大第一层科学覆盖。
后续科学功能测试另定资产、组合、状态和物理领域范围，并维护相应独立数值证据。
