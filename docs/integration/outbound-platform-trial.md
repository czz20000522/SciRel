# 出库路径平台试验材料

这个试验使用已固定的开发包；结果不构成批准发行。材料由 SciRel 提供，宿主的平台能力由接收方实际测试。

## 材料职责

| 材料 | 作用 |
| --- | --- |
| `scirel` wheel 与依赖清单 | 真实安装、加载和科学计算 |
| 同版本 catalog | 发现、科学合同匹配与准确的部分覆盖声明 |
| 物理领域使用指南（HTML / Markdown / Agent JSON） | 说明物理功能、输入、调用与结果含义 |
| 出库 skills | 指导需求理解、必要澄清、能力检索、组合、执行和结果解释 |
| 自然语言 query、输入、实际参考输出及行为预期 | 让平台运行整条消费路径，暴露具体缺口 |

skills 不进入科学 wheel；catalog 与指南也不变成另一套科学实现。接收方自行将材料接入其 Agent 上下文和
可读文件区，实际下载所需依赖、安装 wheel、调用、访问输入和保存/显示/下载结果。提供方不随材料交付
离线依赖集合、平台适配器或预先写好的替代求解脚本。

## 当前出库方法

- `scirel-solving`：理解用户需求、补全实质信息、制定计划、执行与解释结果。
- `scientific-asset-navigation`：对已规范化问题做渐进检索、合同匹配及部分检索范围处置。
- `scientific-project-implementation`：生成用户项目的实际运行入口与结果文件，检验普通复跑、读取结果和接续。

按任务需要加载，保持各自职责。真实科学方法创新、独立科学验收与库整合不属于此次平台材料消费试验，
不因发现缺口而自动扩大到新的模型或来源。

## 试验范围

本轮围绕一个已计算过的径向温度剖面：明确问题直接运行、文件输入、原异常、缺失物理信息的必要澄清、
当前 catalog 没有合适合同、追加问题时保留旧交付并重用确切输入。
前三条有 exact wheel 的实际数值/异常参考；新增对话场景同时明确应观察到的方法行为。
预期行为文档供评估方核对，不要求 Agent 背答案，也不允许复制预期文件冒实际计算。

不强制接收平台使用本项目的 session/job/schema/工具名。可以把 skills 当作普通 Agent 指令加载，
以实际文件读取与 callable 调用记录证明采用；只有上传完成、名称出现在列表、或展示预先保存的答案不足以通过。

## 长期维护

同一版本材料同时绑定 wheel、catalog、使用指南与 skill 内容摘要。科学包能力扩展后，更新对应物理页与
canonical 合同投影；真实试验暴露方法缺口后，小范围更新 skills。保留旧材料和旧失败证据，新版本另存。
平台结论按“实际完成 / 失败或缺口 / 未测试”保存，不从静态审查或独立 Python 调用推断完整平台通过。
