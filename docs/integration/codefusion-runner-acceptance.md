# CodeFusion 中性 Agent 验收

这份验收用于比较 CodeFusion 与 Claude Code/Codex 在同一 SciRel 整合任务上的表现。它不要求
CodeFusion 实现 SciRel 专属 runner、JSON body 协议或修复状态机。

## 固定输入

每次对照记录并固定：

- 同一个只读 L1 目录；
- 同一个冻结 SciRel Git base，以及各自独立的可写候选 worktree/输出目录；
- 同一份 `scirel-integration` skill 内容；
- 等价的文件、终端和测试权限；
- 同一自然语言目标与完成判据。

Git commit 只标识已提交的树。若某轮使用了含未提交内容的工作树，须保存可重建的只读
文件树快照并核对其文件集合与内容身份；仅记录 HEAD 或无法复算的聚合摘要，不足以声称
另一轮使用了相同输入。旧 `neutral-harness-baseline-v1` 的 Claude 运行属于这种情况：
其记录的 SciRel 输入为 `b5dbfc4` 加当时的工作树内容，不等于单独检出该 commit。
使用干净 commit 的新运行可以作为产品能力 smoke，但与旧轮的严格同输入比较需要先恢复
并核验旧快照，或让两种 harness 在同一可重建的新快照上分别运行。

不要向任一 harness 提供另一方的结论或中间文件。可选的 L1 inventory、探针和临时脚本由模型
自行决定是否创建；不得把它们预设为唯一执行路线。

## 通用 Harness 验收

CodeFusion 需要证明的只是中性执行能力：

- 能加载 skill snapshot 并把其身份记录到通用运行证据；
- 能保持 L1 和 SciRel baseline 只读，并只写隔离候选 worktree/任务输出目录；
- 能让模型读取/搜索冻结输入、只修改隔离候选区并执行测试，而不理解 SciRel 领域 payload；
- 能在上下文压缩、进程恢复或失败重试后继续同一任务；
- 能返回以文档为主的候选代码/测试三件套、命令/退出状态、输出 artifact 和有界平台失败分类；
- 权限、credential、tenant、job 和审计字段不进入 SciRel 公共合同。

平台 timeout、runner failure 或权限拒绝不能伪装成科学失败；模型报告完成也不能伪装成专家批准。

## SciRel 结果验收

对两个 harness 的结果使用同一组评价维度：

1. 是否逐项覆盖输入资产，并正确关联当前 SciRel 身份；
2. 是否区分完全重复、等价提案、包含/重叠、变体、参数化、组合、新能力、冲突和未决；
3. 是否识别单位、坐标、符号、模型、边界、状态、离散、失败语义和证据上限差异；
4. 是否形成可执行但尚未应用的候选文档、代码和测试，而不是只有结论摘要；
5. 是否针对实际改动设计并运行充分验证；
6. 是否诚实保留专家必须裁决的科学问题；
7. 是否只改动授权范围并保持 L1 输入不变。

确定性门禁使用仓库现有命令，例如受影响测试、资产文档校验和构建检查。模型为具体科学问题
创建的临时探针按其输出单独复核，不要求提前存在统一脚本。

## 证据

一次对照至少保存：L1 路径/摘要、SciRel base、skill identity、harness 与模型版本、执行时间、
候选文档/代码/测试、逐项判定、运行命令和退出状态、未决问题，以及对输入/输出目录的写入审计。

历史 gseq 运行、固定耗时、调用次数或测试数量只能作为样本，不能成为通过阈值。Pleiades 的
首轮 Claude 运行也只是 baseline；它暴露的方法问题可以修正 skill，但不会自动成为全局规则。
