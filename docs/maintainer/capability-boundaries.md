# 能力边界：包里没有的东西

这一页回答一个问题：**只拿到分发包的人，会在哪里撞到墙上，以及撞墙时他会不会知道。**

它与 [状态快照](status.md) 的区别：状态说"现在做到哪了"，这一页说"这条路本来就不通"。它与
[持久规范与状态的分界](durable-vs-status.md) 的关系：边界是**持久的**——下个版本它大概率还成立，
除非有人明确扩容。

## 1 两类"没有"，后果完全不同

| 类型 | 含义 | 撞上时会发生什么 |
| --- | --- | --- |
| **我们选择不提供** | 明确的设计非目标 | 通常找不到入口，你会立刻知道要自己写 |
| **包内根本没有** | 能力缺口，尚未偿还 | **经常不会报错**：你手上有一个看起来正确的数，只是它少了必要的一环 |

第二类是本页的重点。它们的共同失败方式是：**缺的那一环不参与计算，所以算出来的东西依然自洽、
依然能通过自己的内部检查，只是物理上不是你要的那道题。**

## 2 包内根本没有（消费者实测，附证据）

下面四条来自独立消费者只拿分发包完成三个真实物理任务时的实测
（[C5 缺口清单](../../examples/c5-delivery-acceptance/GAPS.md)）。它们不是"没有便利函数"，
而是**包内没有任何替代路径**。每一行都给出可直接复现的命令或合同事实：

| 缺口 | 具体到哪一步 |
| --- | --- |
| **安全因子 q 与磁剪切：完全没有合同** | `search --q 'safety factor'` / `--q 'magnetic shear'` 都是 `no_candidates`；249 条资产里 0 个 `symbol` 或 `capability` 名含 `safety`/`shear`。`scirel.io.read-geqdsk` 只是把 g-file 里附带的 q 表读进 `mapping`，没有任何算子从磁面几何算 `q(ψ)` 或 `s=(r/q)dq/dr`。 |
| **镜比 / 损失锥角 / 镜点：没有算子** | 12 份 mirror 合同**全部**把损失锥边界当**输入**（`xi_tp`）；没有一份接收磁场剖面返回 `B_max/B_min`、`θ_loss` 或 `z_m`。风险不是"多写几行"，而是**纠错面消失**：`xi_tp` 错了，下游照样得到一个自洽、精确到 1e-15 的谱，没有任何东西能发现喂进去的边界是错的。 |
| **没有三维 Cartesian ↔ 柱坐标** | 只有 `scirel.sampling.meridional-polar-forward/-inverse` 这一对**二维子午面**变换。任何带环向角的题目消费者得自己写那一腿。 |
| **平衡 → 镜域：没有合同级交接** | `scirel.equilibrium.compute-equilibrium` 返回的 `EquilibriumResult`，其 `outputs.units` 字面是 **`source-unspecified`**；mirror 域要的 `psi` 单位（Wb 还是 Wb/rad）明说是调用者责任。两端之间没有任何合同声明字段、单位、符号约定的对应关系。 |

消费者撞到这些时的正确行为是**说出来**："这个平衡的边界 q 和剪切，包内没有这个能力"——这句话必须由人说出来，不能让检索的 `no_candidates` 自己扮演结论。


## 3 跨域组合的系统性缺口

消费者跑了 6 条跨域任务，**6 条全部不能只靠包完成**（[C4 第二轮缺口](../../examples/c4-usage-acceptance/round2/GAPS.md) B8）。复核后仍成立的三类断点：

1. **单位只活在合同文本里**：返回值没有单位标签，跨域交接必须靠人读合同确认。六条任务的断点
   几乎都在这里。
2. **轴序不统一**：`[R, Z]` 与 `[Z, R]` 在不同入口之间并存，没有声明层能提示你正在错配。
3. **没有适配器**：例如一维 profile 到 `(2,2,3)` 的 forcing，只能自己想 reshape；自行 reshape
   后偏差 0.146（判据 fail）——**它不会报错，它只是算错**。

## 4 我们选择不提供（设计非目标，不是缺口）

- **不提供全局运行框架**：只给零件，不组装整道题（详见 [参照项目](reference-projects.md)）。
- **不做自动物理判据**：门禁只检查结构与声明一致性，不判科学对错。
- **不提供容差自适应**：容差是合同的一部分，不由库代你选。

这三条撞上时通常能找到别的入口或明确报错，因此风险等级低于第 2、3 节。

## 5 为什么这些缺口值得单列一页

因为**它们不会自己报名**。`AGENTS.md` 第 7 条管的是"检查器的输出是否有分辨力"；这一页管的是
**能力本身是否有分辨力**——当缺的那一环不在计算路径上时，输出对"任务是否被正确完成"没有分辨力。

外部消费者的结论值得原样引用：

> 缺的不是便利函数，而是把"镜比→损失锥边界"这一环，而缺了这一环，**下游算得再准也没人发现输入错了**。

## 6 谁该更新这一页

新能力解冻后，任何把上述条目补上的批次**必须同时删掉这里的对应段**，而不是在下面追加"已支持"。
两处各写一份就会漂移——这是 [持久规范与状态的分界](durable-vs-status.md) 的同一条理由。
