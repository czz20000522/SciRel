# 对外讲解：不同听众的讲法、常见问题与建议顺序

状态：**持久**。讲法不随版本变，所以这一页和总纲一样"少修改、一直有效"。
本文件不含规模数字、进度和领域清单——那些在 [状态快照](status.md)，讲的时候现场取。

同一个项目，讲给物理专家和讲给软件开发者，重点完全不同。本文件按听众分开给要点，
再给一份可直接照念的 30–45 分钟流程。

## 1 讲给物理专家时的重点

物理专家最关心的是：**这个东西算得对不对、我能不能信。**

1. **合同要写清适用范围和失败行为**，这是要求；某一项能力是否完全落实，要看它自己的实现、测试与
   已知限制——**不能把全库目标概括成全库已经完成**。
2. **关键预期值要有可核对的依据**：解析解、文献、守恒律，或来源输出（最弱的一类，必须显式标出）。
   独立依据与"和来源一致"要分开讲；尚未核对到原表的文献值要如实说明。
3. **物理正确优先于忠于原代码，但要证据，而且要先排除"有意的近似"。**
   可以讲质子–氢截面的完整故事（见 [`why-and-how.md`](why-and-how.md) §3.6.4）。
4. **数值允许合理误差。** 浮点科学计算按有依据的绝对/相对容差比较；但"模型有几个百分点近似误差"
   与"浮点尾数差异"不是同一件事。判断精度是否满足研究要求的方法见 `why-and-how.md` §3.6.5。
5. **专家精力应该用在真正需要判断的问题上**：工具负责机械检查，独立评审负责有依据的核对，
   证据不足或需要选定约定时开工单、异步处理。
6. **欢迎专家贡献的方式**：处理工单、提供文献依据、指出某份合同的物理假设写得不对。

**可能的质疑：AI 写的物理代码靠得住吗？**
回答思路：不能因为作者是人或 AI 就直接判定正确，也不能直接判定错误。我们要求可核对的依据、
能发现典型错误的测试、以及适当级别的评审；同时**披露未验证的部分**。
这些机制的作用是**帮助暴露错误**，不保证永远不出错——早期参照因子和精度声明先后被纠正，
恰好说明评审结论本身也要持续接受证据检验。

## 2 讲给软件开发者时的重点

软件开发者最关心的是：**架构是否清晰、能不能扩展、工程上是否可靠。**

1. **实现说明有唯一准绳**：代码与 docstring 里可派生的字段同步到合同和文档；物理正确性另由独立证据支撑。
2. **分层架构加自动检查**：六层，依赖只能往下；用 AST 扫描全部 import（包括写在函数体内的），
   发现"往上借"或同层互借就判红。
3. **统一的接口约定**：模型族用 `method=` 选；迭代结果返回收敛状态；参数显式写出、不用
   "什么都能传"的字典；多个返回量用带名字的 `Result`。
4. **为 agent 设计的报错与渐进式披露**：这是比较新的设计方向，值得重点讲——报错自带下一步，
   选错名字列出全部合法值，信息分"大类 → 小类 → 细节"三层。
5. **供给链像工厂流水线**：标准化的"拆解包"是线与线之间唯一的接口，质检前移（出厂检验），
   合并线只判不改。
6. **变异测试**检查"测试能不能发现选定的错误"，它不代替科学验证，也不要求对允许范围内的浮点差异判错。
7. **多 agent 并行开发**：一个 issue 一个分支一个 worktree，讨论留在 PR 上而不是聊天里。
8. **工程纪律**：项目内固定环境、运行产物可定位、按代价分层检查、保留执行分母与原始失败、
   不留没有必要的兼容分支。
9. **观测必须是三态**：通过 / 失败 / 未观测。丢信息的观测不会报错，它会邀请读者用先验补那一位，
   而补出来的总是"还好"的故事。这是本仓库代价最高的一类缺陷，见
   [观测完整性](observation-integrity.md)。
10. **当前主线**是还债与结构设计：重点解决能力增长时的边界、依赖、模型替换与组合问题，
    而不是把能力数量做大（进度见 [状态快照](status.md)）。

**可能的质疑：为什么不直接用通用数值库加一堆脚本？**
回答思路：通用数值工具能解决许多底层计算，项目**应当**复用它们（本仓库就是建在 NumPy/SciPy 之上）。
SciRel 额外维护的是聚变与等离子体科学关系的模型、单位、适用范围、证据和统一使用入口。
脚本也可以写得很好；这里要解决的是这些**科学约定**怎样跨项目长期维护和复用。

**可能的质疑：合同和代码会不会对不上？**
回答思路：能派生的字段尽量派生，已有同步检查覆盖部分一致性；但物理文字和全部限制并非都能自动判断。
发现矛盾时按真值链核对并修正，**不能宣称"有门禁，所以绝不漂移"**——
更准确的说法是：能机械判定的部分有检查器站岗，不能判定的部分是明确的软规则、靠评审把关。
两者分别有哪些，见 [持久规范与状态](durable-vs-status.md) §3。

## 3 常见问题

**Q：会发布到 PyPI 吗？**
A：当前没有公开发布计划，以内部与内置能力使用为主。发布状态是会变的事实，见 [状态快照](status.md)。
就项目决策而言：集中改名和统一接口，在还没有大量外部依赖时做，比有了之后做容易得多；
但内部消费者也要一并迁移。

**Q：和那些"一键跑完整个模拟"的集成程序有什么区别？**
A：集成程序管的是**整个任务怎么运行**。SciRel 提供可复用、有合同的科学关系，也可以提供有独立合同的
通用组合；**任务专属的总体编排由用户程序负责**（见 [`why-and-how.md`](why-and-how.md) §7）。

**Q：为什么要从别人的程序里"拆"，不自己从头写？**
A：现成程序和材料能提供有价值的关系、定义与验证线索。但"来源存在"不等于"全部可靠"：
要解除不必要的组织耦合、按本库接口整理、补齐范围与证据；有错误的，还要有依据地纠正。

**Q：拆别人的代码有版权问题吗？**
A：项目要求核对具体来源的许可与署名条件，并分别维护公开材料与私有记录。
私人路径、未公开的来源身份和公开文献引用不是一回事。**调整函数名、或保存一份"来源记录"，
都不能自动证明已满足某项材料的分发条件**；具体材料要按其许可单独核对。

**Q：目标很广，是不是所有物理方法都要立刻收进来？**
A：不是。广泛覆盖是长期目标；独立量子计算体系不作为当前建设方向，但已有碰撞、反应数据所需的
微观物理依据仍要核验。新能力的接收取决于维护者划定的能力边界与解冻决定（当前边界见 [状态快照](status.md)）。

**Q：一个新函数从无到有要经过哪些步骤？**
A：拆解者找到关系 → 和已有合同比对（四选一） → 写代码、测试、证据和合同 → 跑校验器（含变异测试）
→ 交出拆解包 → 合并线判题、必要时评审或开工单 → 合并入库 → 进入分发包。
六步的判据见 [`supply-pipeline.md`](supply-pipeline.md) §4。

**Q：如果两个物理专家意见不一致怎么办？**
A：先分别核对假设、约定、数据和推导。仍缺决定性证据时，列出能合法选择的方案、影响与证据缺口，
按工单协议形成**署名**裁决。裁决可以选择一个约定、或明确接受一种风险——
**它不等于用多数票证明了一条物理定律**；等待期间先执行安全默认。

**Q：提供的示例压缩包对新版本有什么约束？**
A：它只说明分发思路可以实现，**不是**新版本的合同、接口或目录标准。我们按当前实现与新的结构约定
统一生成合同、wheel、索引与 skill，不去修补示例包，也不为它保留兼容入口。

**Q：是不是所有计算都必须和参照值精确相等？**
A：不是。浮点科学计算通常按有依据的绝对/相对容差比较，模型近似还要单独说明。
禁止的是**为了让一个错误结果通过而随意扩大容差**，不是禁止合理的近似相等。
详见 [`why-and-how.md`](why-and-how.md) §3.6.5。

## 4 建议的讲解顺序（30–45 分钟版）

| 段 | 时长 | 讲什么 | 详见 |
| --- | --- | --- | --- |
| 开场 | 3 分钟 | 一句话定位；再补一句最容易被忽略的：**"程序能接收某个输入，不代表这个范围已经有物理证据"** | `why-and-how.md` §1 |
| 为什么做 | 5 分钟 | 聚变代码的四种病，以及 agent 这个新用户 | `why-and-how.md` §2 |
| 核心思想 | 12 分钟 | 合同用**药品说明书**作比喻；软件当前行为与物理正确性分开判断；六层楼与水往下流；模型族与 `method=`（配上"合还是分"的例子表）；为 agent 设计的报错 | `why-and-how.md` §3 |
| 怎么检查正确性 | 10 分钟 | 物理正确优先但要证据（讲质子–氢截面的完整故事）；变异测试用**消防演习**作比喻；分级评审与工单；用容差解释"模型近似"与"浮点尾数"的区别 | `why-and-how.md` §3.6、§5、§6 |
| 能力从哪来 | 7 分钟 | **工厂**的比喻：三条线、拆解包、质检前移 | `why-and-how.md` §4、`supply-pipeline.md` |
| 谁在干活 | 3 分钟 | 人、设计评审助手和一群 bot 怎么靠证据协作 | 本文件 §2 第 7 条 |
| 现状与路线 | 3 分钟 | 只讲方向（还债、结构设计、统一交付），不背数字 | `status.md` |
| 问答 | 余下 | 物理专家看 §1、软件开发者看 §2，通用问题看 §3 | 本文件 |

**一句话收尾：**

> 我们在为聚变与等离子体研究建设一套标准科学零件库：把模型、单位、精度、适用范围和证据写清楚，
> 让人和 AI 都能检查、复用和组合。
