# AOCI 项目索引与增量维护

AOCI 维护 SciRel 开发项目的框架认知和源码关系，覆盖科学实现、组合任务图、文档、合同、测试、skill、构建与平台工具。科学资产的唯一正式合同仍是 `scirel.asset-document.v1`；catalog 是其发现投影。AOCI 不授予 D1 资格、科学认可或发行批准，也不成为科学函数的运行依赖。

## 先按任务和当前工作区选择证据

先核对任务目标、实际 Git 根/分支、目标对象以及已有索引的范围和身份，再决定是否需要 AOCI 完整认知。开发项目索引可能同时含历史科学样本、科学库实现和开发工具；其数量或 `full` 配置不表示它与每个任务相关。父 checkout 的历史索引不能代表另一洁净主线、来源项目、D0 副本或容器的当前状态。

| 当前任务 | 首先读取的证据 | 完整 Overview 的条件 |
| --- | --- | --- |
| 远端进程状态、任务调度或交付接续 | 确切运行/交付身份、轻量 handoff 和实时进程/provider/资源状态 | 仅当后续判断确需与该索引匹配的系统全景；本身不需要 |
| 开发工具、skill 或调度脚本修改 | 相关需求、实际源码、调用者、配置和相关测试 | 局部证据不能回答所需的跨系统问题，或任务明确要求严格完整认知证明 |
| 具体科学内核或 TaskGraph 修改 | 该资产的合同、实现、测试、来源及直接/反向依赖 | 所需全景确实属于当前索引范围，而非因存在其他科学条目就全量读取 |
| 当前相关系统全景审查或严格完整认知验证 | 匹配当前根、版本、服务和范围的 AOCI 认知 | 需要且没有可靠完整认知时显式发起完整链 |

上下文压缩使旧的完整认知证明失效，不把状态查询或局部开发自动升级为全景审查。保留任务决定、源码/交付身份、待办和写入/Recovery 状态，重新核对当前任务所需证据；不得用旧 Whole-Index 摘要或 receipt 冒称恢复了完整认知。确需重新证明时，再以 `context_compaction` 和新的事件身份按当前协议重载。

用户与项目决定 Host 的任务范围和恢复方法；工具通用说明中的认知前置不自动扩大该范围。没有完成完整链时保留未验证状态。显式发起 Overview 后，仍按真实 Schema、cursor、交付确认和一次 Attestation 完成整个所选范围，禁止缺块、拼接旧正文或旁路补答；写入、CAS、Recovery 和安全停点不因按需路由而减弱。scope 只使用当前工具实际支持的值，`scope=project` 不等于任意目录过滤。无法表达所需范围时，使用相关源码/合同完成有界任务并说明认知限制，或另行提出受治理的范围调整；不伪造 scope 或全景证明。

## 初次建立与工作树边界

来源项目的 D0 先完成或复用初始索引，再整理源码，对稳定的变化增量维护，最后冻结与源码一致的索引；
具体阶段顺序见 [D0 流程](../development-process.md#d0整理来源并固定交付)。索引可以描述尚待清理的源码，
但首次条目仍须基于真实证据并通过当前协议；不能把已知无效条目留到第二遍才处理。
首次建立、变化维护和语义纠错使用各自适用的实时 Guide，不在普通首建结束后自动开启全量
`cognition_optimization`。语义错误可能在源码未变时存在，应按已证实的影响范围走合法纠错路线；
没有新变化或疑点时复用有效结果。全仓指纹检查不等于要求模型再次创作所有条目。

这里的 skill 只补项目边界与任务路由，AOCI 自身的 Rules/Guide 负责索引协议；不另设一套状态机。
普通首建不预设多子代理或每批外部接收。选择了委派与独立审查合同的任务仍须满足其 final、版本绑定、
语义差异复核和真实提交门禁；阶段独立验收也按原合同保留，不把这些条件泛化为所有索引任务的额外流程。

先核对实际 Git 根、现有工作树、未提交修改及本机二进制身份。新项目按当前 capabilities、init 和 Guide 建立范围、Baseline 与语义索引；既有项目复用索引，不重复初始化或强制扫描。完整索引表示当前明确范围内的对象均得到协议规定的处置，排除项和观察项须显式可检查；不表示全部科学行为已验收。

每个 worktree 的机器 MCP 配置绑定自己的绝对根；共享认知文件随代码版本演进，机器状态和配置按 AOCI 布局忽略。合并后的源码、范围和索引差异仍需核对，不能将另一工作树的 receipt 或未维护状态当作本树完成证据。并行整合保持单写者协调正式索引事务，避免覆盖其他贡献者的条目。合并或绑定源码变化后，丢弃旧 candidate/preimage 并取得当前批次；不复制其他 worktree 的机器状态。

## 随整合批次增长

| 变化 | 维护范围与依据 |
| --- | --- |
| 新增来源项目或科学家族 | 已接收 D1 的资格与限制、D2 保留实现、稳定身份及直接依赖；引用冻结输入，不回写上游 |
| 新增或改变 Operator | 实现及默认值/失败合同、必要公共导出、相关测试和稳定后的唯一 exact document |
| 新增或改变 TaskGraph | 组合目标、直接算子/子图、端口与顺序、状态/反馈上限、反向消费者及相关测试 |
| 共享实现或合同变更 | 共享拥有者、实际调用者、受影响图与测试选择；不能只维护当前入口 |
| 文档、测试、skill 或构建变更 | 对应职责、证据上限与关联实现；测试通过和设计意图分别记录 |
| 删除、吸收、替换或重命名 | 当前身份和关系处置、保留来源/许可依据、兼容与依赖变化；按治理协议移除旧条目 |

日常内循环先修改代码和必要证据，按 `scripts/check.ps1 -Mode affected` 验证改变及反向依赖；不能归属的源码变更仍全套回落。代码稳定后维护 AOCI；不要为每个中间编辑、算子或局部回报生成一次全量索引、正式科学文档或跨阶段流程。

稳定批次记录明确比较基线与完整增删改集合，重命名保留旧、新两端，并结合旧、新依赖核对消费者。当前 selector 的默认路径包含相对 HEAD 的未提交和 untracked 变化；`-BaseRef` 只比较提交到 HEAD，不能同时代表本地待提交修改。删除或改名不能假设当前 catalog 自动恢复旧关系；必要时通过 `-ChangedPath` 显式传入完整路径集合，无法确认影响则全套回落。

维护者读取当前 Rules、Guide/Maintain 返回的实际 Schema、候选与绑定证据，由模型创作完整语义。每次提交完整机器批次，保留 source digest、candidate 和 preimage 身份；成功后若仍有 remaining，自动取得下一批直至处理完。批次上限控制传输与事务大小，不改变覆盖要求。发生 repair、stopped 或 Recovery 时遵从实时合同，不盲重试或手改 Volume。

## 控制存储与上下文增长

开发认知与科学能力发现分开：AOCI 描述框架、职责和强关系；科学发现遵循 [catalog 合同](../catalog.md)的分片、渐进披露与依赖闭包设计。当前 `scripts/build_catalog.py` 仍全量读取已验证文档，生成 routes/summaries/reverse-dependencies 的 `all.jsonl` 和按身份摘要目录存储的 exact records，确定性构建新的完整 snapshot。领域分片与未变化分片复用是后续规模化工作，AOCI 条目增量维护不代表 catalog 已实现增量构建。不得将所有算子合同复制进 AGENTS 或全局 registry，也不得全量 import 来发现能力。

每个稳定整合批次后记录 Scope/Budget 中的覆盖对象数、待维护数、观察项和实际预算结果，同时记录新增对象、token 增量、批次数与维护耗时。增量语义创作只处理工具绑定的变化对象；全仓指纹核对和完整 Overview 的成本仍随仓库及索引增长。模型按上面的任务路由决定是否加载完整框架，局部任务可使用工具实际支持的 search/get_entries 与源码定位；只有确需完整认知时，局部检索才不能替代该完整链的续传、交付确认与 Attestation。

当索引增长触及机器预算、延迟或传输限制时，先检查当前工具是否支持受治理的范围调整、分卷或职责聚合，再给出具体候选范围和覆盖影响。重复生成的 catalog 分片/运行证据是否适合观察层取决于引用关系与当前合同；不因文件数量多而自动排除测试、文档或科学实现。需要改变范围时走 Scope Plan/Preview/授权/Apply；不能直接修改 Baseline、伪造语义批次或放宽预算来掩盖未覆盖对象。

## 稳定批次的完成证据

索引建立或维护批次按当前版本执行 Verify、Check、Guide 与 Scope/Budget 检查。完成报告绑定实际工作树、代码状态与索引身份，明确剩余候选、观察项和恢复事项；索引对齐、框架认知可靠、科学回归、来源资格、人工认可与发行门禁分别报告。AOCI 本身不进入科学 wheel，不要求运行用户函数时连接 MCP、数据库或网络。

维护与任务阅读范围分别决定。若用户限定本次只修正文档路由、不改正式索引或不运行维护，保存受管理文件的变更身份并明确标记索引待对齐；不能为消除这个状态强迫读取无关全量，也不能手改正式索引。历史科学内容与开发框架的范围重构是另一个受治理工作：先测量实际混合范围、提出覆盖影响，再按当前 Scope/Guide 执行；仅修正路由不表示已经完成范围重构。

工具的 init/升级可能重新生成 AGENTS 托管块并带回通用默认入口。本项目在托管块外保留任务适用性规则并优先用于调用决策；生成后核对其一致性，不把任务路由纠正描述为 AOCI 产品模板已修复。
