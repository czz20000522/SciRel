# 科学运行依赖基线

SciRel 尚未公开发行，维护中的科学实现共用一套较新的稳定运行依赖，不为历史试验长期保留不同版本的兼容分支。
当前选定 Python 3.14.7、NumPy 2.5.4、SciPy 1.18.1、Matplotlib 3.11.2、netCDF4 1.7.4 与 mpmath 1.4.1。
Python 的小版本线由 `pyproject.toml` 限定，开发解释器补丁版由 `.python-version` 固定；
科学依赖及构建工具的直接版本以 `pyproject.toml` 为唯一依据，`uv.lock` 固定解析后的传递依赖和分发摘要。
新增科学依赖先评估实际需要、许可证、平台 wheel 和已有依赖兼容性，再更新这一基线。
本基线统一版本选择，不要求来源运行、科学 wheel 和 SciRel 项目开发安装同一套依赖。
三类环境的用途和验收按[依赖边界](project-and-distribution.md#三类依赖与独立环境)分别确定。

## 安装与构建

`uv sync --locked --extra test` 用于 SciRel checkout 的独立开发环境，不是来源预处理或用户安装的通用命令。
来源环境按 D0 保留入口和实际对照需要，从上游依赖中选择必要子集；为复现来源行为确需不同版本时，
在来源环境中固定并记录差异，不强制升级后把行为变化算作 SciRel 误差，也不把旧依赖带入新 wheel。
科学计算使用对应项目的独立容器；
Mac 开发检查可以使用独立虚拟环境，但不据此推断 Linux、其他架构或完整科学能力已经通过。
文档渲染工具另由 `tools/docs/sphinx/requirements.txt` 固定，不进入科学 wheel。
Git、PowerShell 是项目维护和检查脚本的开发工具，也不进入科学运行依赖。
构建、测试、独立参考计算与文档工具按本次开发任务选择；仅有科学 wheel 的安装环境不要求这些工具。

所选科学包只声明其实际使用的依赖子集，版本必须取自统一基线；实际闭包包括传递依赖和必要本地组件。
独立参考计算库若未被运行实现调用，留在验证环境。同一依赖进入多类环境时分别说明用途，
共享的受维护库使用统一版本，来源对照所需的历史版本例外单独绑定。
`scientific_runtime.py` 对历史选择中仍兼容的范围固定当前版本；不兼容、未知、带条件或额外来源的要求会拒绝构建，
须先完成明确的依赖与实现迁移。该工具只校验并固定传入子集的版本，不判断某个依赖是否有科学必要，
也不把整套基线追加到子集。所选构建回执绑定基线文件摘要，科学文件仍按原选择逐字核验。
正式审核构建要求源码树已使用此基线，不在准备发行时悄悄替换已审核环境。

## 历史交付统一与验证

已冻结的 wheel、源材料、失败记录和审核依据保留原字节。需要继续维护的能力全部进入同一依赖基线的后继版本，
不因历史冻结而豁免；允许重写实现，但必须保留科学合同和独立验证依据。
原环境的通过记录只证明原交付；后继版本需要重新绑定实现、文档、catalog、依赖和确切 wheel。
文档中的旧实现版本不能直接批量改成同一版本来制造验收。

迁移遵循以下顺序：

1. 核对完整核心能力、单位、定义域、状态、默认值与失败行为。
2. 保留迁移前的失败证据；科学行为改变先冻结失败回归，再依据物理和数值推导修正。
3. 在对应依赖子集的环境运行受影响的科学测试、独立计算及真实使用案例。保持有效断言和数值容差；
   测试若与已接受的科学修正冲突，必须说明推导与新旧合同差异，不能照着运行输出修改期望值。
4. 构建精确所选 wheel，在无 SciRel checkout、无原来源源码、无网络的环境安装执行，验证依赖闭包与核心任务。
5. 更新唯一正式资产文档及其中文手册、API/canonical/catalog 投影，独立接收后再计算完整项目交付。

本基线是维护政策，不授予任何项目科学资格、人工认可或公开发行许可。
当前迁移按 Pleiades 完整核心能力优先推进；其他历史交付依次生成后继，不能将版本固定本身算作统一完成。
完整拆解对所有项目均指：安装 SciRel 后脱离原源码仍保有所声明的全部核心物理能力，绘图等非核心能力单列。

## 当前累积科学选择

`scientific-core-20261014.json` 的运行闭包采用上述五个 Python 依赖。mpmath 在有理 Padé 系数生成的运行实现中被实际调用，故由仅测试工具升为可选科学选择的运行基线成员；并非每个科学子集都必须安装它。
磁化波的随包 `.m` 实现还需要外部 Octave 8.4.0（当前验证 Linux ARM64）；pip 不会安装该系统运行时。Git、PowerShell、pytest 和文档渲染仍属项目开发，不属于此 wheel 的运行要求。
