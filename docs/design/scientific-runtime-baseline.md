# 科学运行依赖基线

SciRel 尚未公开发行，维护中的科学实现共用一套较新的稳定运行依赖，不为历史试验长期保留不同版本的兼容分支。
当前选定 Python 3.14.7、NumPy 2.5.4、SciPy 1.18.1、Matplotlib 3.11.2。
Python 的小版本线由 `pyproject.toml` 限定，开发解释器补丁版由 `.python-version` 固定；
科学依赖及构建工具的直接版本以 `pyproject.toml` 为唯一依据，`uv.lock` 固定解析后的传递依赖和分发摘要。
新增科学依赖先评估实际需要、许可证、平台 wheel 和已有依赖兼容性，再更新这一基线。

## 安装与构建

在独立项目环境执行 `uv sync --locked --extra test`。科学计算使用对应项目的独立容器；
Mac 开发检查可以使用独立虚拟环境，但不据此推断 Linux、其他架构或完整科学能力已经通过。
文档渲染工具另由 `tools/docs/sphinx/requirements.txt` 固定，不进入科学 wheel。
PowerShell 是跨平台检查脚本的开发工具，也不进入科学运行依赖。

所选科学包只声明其实际使用的依赖子集，版本必须取自统一基线。
`scientific_runtime.py` 对历史选择中仍兼容的范围固定当前版本；不兼容、未知、带条件或额外来源的要求会拒绝构建，
须先完成明确的依赖与实现迁移。所选构建回执绑定基线文件摘要，科学文件仍按原选择逐字核验。
正式审核构建要求源码树已使用此基线，不在准备发行时悄悄替换已审核环境。

## 历史交付统一与验证

已冻结的 wheel、源材料、失败记录和审核依据保留原字节。需要继续维护的能力全部进入同一依赖基线的后继版本，
不因历史冻结而豁免；允许重写实现，但必须保留科学合同和独立验证依据。
原环境的通过记录只证明原交付；后继版本需要重新绑定实现、文档、catalog、依赖和确切 wheel。
文档中的旧实现版本不能直接批量改成同一版本来制造验收。

迁移遵循以下顺序：

1. 核对完整核心能力、单位、定义域、状态、默认值与失败行为。
2. 保留迁移前的失败证据；科学行为改变先冻结失败回归，再依据物理和数值推导修正。
3. 在统一环境运行受影响的科学测试、独立计算及真实使用案例。保持有效断言和数值容差；
   测试若与已接受的科学修正冲突，必须说明推导与新旧合同差异，不能照着运行输出修改期望值。
4. 构建精确所选 wheel，在无 SciRel checkout、无原来源源码、无网络的环境安装执行，验证依赖闭包与核心任务。
5. 更新唯一正式资产文档及其中文手册、API/canonical/catalog 投影，独立接收后再计算完整项目交付。

本基线是维护政策，不授予任何项目科学资格、人工认可或公开发行许可。
当前迁移按 Pleiades 完整核心能力优先推进；其他历史交付依次生成后继，不能将版本固定本身算作统一完成。
完整拆解对所有项目均指：安装 SciRel 后脱离原源码仍保有所声明的全部核心物理能力，绘图等非核心能力单列。
