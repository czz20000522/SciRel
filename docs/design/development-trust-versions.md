# 开发、待审与可信版本

开发、审核和发行属于 SciRel 项目层；用户科学包不加载审核状态、来源快照或 skill。
版本的实际内容由确切提交、所选资产、依赖和 wheel 摘要定义，分支/worktree 只提供隔离工作空间。
具体规则见 [开发项目与科学包交付](project-and-distribution.md)。

## 三条边界

- **开发版**：在隔离分支比较 D1 交付、开发/可信基线及当前未发布候选，完成科学判断、去重、修正、测试和开发 wheel；可用于披露信任状态的内部 D3，不因能运行而获批准。
- **冻结待审版**：保留代码稳定后，固定 expert 实际看到的代码、唯一 exact documents、测试和证据。上传固定逐项初始版本；查看记录所见内容，实质变更形成关联 successor。
- **可信版**：专家根据上一可信版到待审版的累积科学差异及证据认可确切内容。许可、依赖、实际安装验证和发行授权仍须完成；认可不等于自动发布。

## 当前主线

当前 `0.2.0.dev0` 没有科学资产或真实批准/发布，只有包骨架和开发工具。
`catalog/assets/` 为空，`provenance/mainline-release-index.dev.json` 是新主线的空索引。
历史 52/132 样本、混合来源开发快照和候选审核记录已迁往 [历史开发测试线](../history.md)，
不继承为主线基线或批准事实。合成工具夹具也不计为科学资产、公开 catalog 或真实专家决定。

默认先完成来源项目 D1 并保存可独立接续的交付，再由新 owner 接收 D2/D3。
明确约定的局部试点可先接收有界合格批次，但不自动逐算子启动整链，也不代表项目完成。
时间间隔或换 owner 不使仍有效证据失效；实际事实变化和归属不足才补必要验证。

## 索引与证据

索引由 D2 owner 单写，按确切内容追加开发快照、待审候选、证据、关联版本与最终发行结果。
它选择和绑定版本，不复制科学字段；exact document 保持唯一科学合同，catalog 是发现投影。
未来每项记录固定来源资格、Git/artifact、wheel/catalog 与实际验证，历史索引不重写。
`pending_unapproved` 仅表示未批准；缺少源对照不能被简写成只等人工拍板。

冻结只固定版本，不证明输入通过 D1。wheel 可运行、文档 complete 或 D2 测试不能替代来源验证。
历史输入如被选作比较对象，必须给出真实资格与缺口，不因其已有旧源码/测试而自动进入正式库。

审核基线是上一可信版；当前没有可信基线也不阻断开发。人类看到稳定累积增量，
不逐开发提交审批。未变且未被依赖变化影响的能力可复用原证据；改变实现、合同、依赖或运行环境
按实际影响复核。机械版本或排版调整保留可核对差异，不自动重做全库科学计算。
专家只认可子集时，在独立 successor 中排除或返工其余内容，不把混合快照整体标成可信。

## 并行开发与固化

整合、候选与维护分支分别使用自己的 worktree、环境和输出；旧可信版本与冻结来源只读。
主线合并和发行索引由明确 owner 串行协调；对照当前基线处理科学身份、依赖和 patch 冲突，
不采用整批覆盖或 last-write-wins。新的提交/构建不继承旧工件摘要或未经核对的批准。

候选提交后原模型运行可结束，工作台异步审核；批准后另有短任务确认实际内容同一并准备发行。
现有 workflow/plugin API 含单 draft fixture，逐项发布准备器仍是开发期机制。
增量发行缺上一可信版本文档/支持模块的可验证继承输入，真实审核宿主的认证/授权也不能由本地
JSON 摘要证明。通用工具测试通过不解除这些实际发行门槛。
